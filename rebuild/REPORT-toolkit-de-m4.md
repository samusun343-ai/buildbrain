## 項目1: シェル/グリーターのフォント未インストール（実機ブロッカー）

- 原因: フォント未インストール時は `tk_canvas_draw_text` が何も描かない仕様
  （tk.h 明記。フォールバック計量はヘッドレステスト専用）。製品エントリ
  （braindesk2.c / session.c / shellui.c / braingreeter2.c）は一切
  `tk_font_install` を呼んでおらず、実機起動では文字が一切描画されない状態だった。
- 修正:
  - `shell/src/shellui.c`: `bd_shell_new` で「現在フォントが無ければ製品ローダ
    （`tk_font_load_bundled`）で読み込み・インストールし、シェルが所有、
    `bd_shell_free` で解放」。埋め込み側が既にインストール済みなら触らない。
    braindesk2 / session の両経路をカバー。
  - `shell/greeter/braingreeter2.c`: `gui_main` に同パターン（全終了経路で解放）。
- テストで固定:
  - `shell/tests/test_session.c` +5: フォント無しではベアラベルが描けない →
    製品エントリ経由で描ける、セッション解放後にフォントが外れる。
  - `shell/tests/test_greeter_font.c` 新設（6件）: shot_greeter と同じシーム方式で
    braingreeter2.c を include し、フォントを一切入れずに起動して初回フレームに
    実グリフがあることを検証。`shell/Makefile` にターゲット追加。
  - `braindesk2 --check` 正常（first frame 768000 B / quiet 0 B）。

## 項目2: スライダつまみ/トグルスイッチの砂時計描画

- 原因: `src/tk_draw.c` の `tk_canvas_fill_round_rect` の inset 計算が逆転
  （角中心行で inset 最大・端で 0）。radius = h/2 の完全角丸
  （スライダつまみ 14×14 r7、スイッチトラック 36×20 r10、ノブ 16×16 r8）が
  砂時計/蝶ネクタイ形になっていた。
- 修正: ピクセル中心ジオメトリで書き換え
  （`dyc = 2*(radius-y)-1`、half = (isqrt(4r²−dyc²)+1)/2、inset = radius−half）。
- テスト: `tests/test_tk.c` +25（プリミティブの行幅プロファイル＋実 paint 経路での
  スライダ/スイッチのピクセル検証）。再撮影でも円形つまみ・ピル型スイッチを確認。

## 項目3: フォントサブセット再生成＋サプリメントチェーン

- `fonts/build_subset.py` 拡張:
  (a) BASE_RANGES に数学演算子 (0x2200–0x22FF) を追加（U+2212 はここが欠けていた）。
  (b) BIDF v3 の SUPP 表記（`libbrainime/m3work/supp.tsv`）を取り込み
      （U+591B 夛・U+5F0C 弌 は SUPP のみに存在し M3 ビルド時点で未統合だった）。
  (c) UI 使用文字を src/ include/ shell/ apps/ osk/ の全 .c/.h から収穫。
  (d) カバー率報告を辞書/SUPP/コーパス/UI 別に拡張。(e) サプリメント生成を追加。
- 再生成結果: 本体 `fonts/brainui-jp-subset.ttf` = 1,290,908 B / 5,490 グリフ
  （旧 1,282,032 B / 5,354）。
  カバー率: 辞書 4561/4561 コードポイント・180,000/180,000 エントリ、
  SUPP 1126/1126・35,116/35,116 エントリ、コーパス 299/299 — いずれも 100%。
- UI 使用文字は本体のみで 711/735 (96.73%)。欠け24字は Noto Sans CJK 自体に
  存在しない字（OSK 記号ページの Ħ Ł Š Ÿ・ギリシャ変形 ϑϕϖ 等、calc の ʸ ˣ ⁻ ₀ ₁ ₂、
  player/recorder の ⏭ U+23ED・⏮ U+23EE・⏸ U+23F8）。対策としてサプリメント2種を
  生成し、チェーン全体で **UI 735/735 = 100%**:
  - `fonts/brainui-jp-supplement.ttf`（55,736 B、498 グリフ、DejaVu Sans 由来、21字）
  - `fonts/brainui-jp-symbols.ttf`（1,204 B、3 グリフ、Noto Sans Symbols 2 由来）
  - 帰属は `fonts/NOTICE.supplement.txt` に新規作成。
- `src/tk_font.c`: `tk_font_load_bundled` が本体と同じディレクトリのサプリメントを
  自動でフォールバックチェーンに接続。所有権のため `fallback_owned` フラグを新設
  （ローダ接続分は `tk_font_free` が連鎖解放、公開 `tk_font_set_fallback` は
  呼び出し側所有のまま — 既存 test_font の挙動不変）。ルート Makefile の install
  規則にもサプリメント2種＋NOTICE を追加。
- テスト: `tests/test_tk3.c` +6 グリフ（U+2212/591B/5F0C/0142/23F8/23ED）。
  再撮影で calc の「−」キー、アシストの「音量−/輝度−」、player の ⏮/⏭ が
  表示されることを確認。

## 項目4: デスクトップのピン留めアイコン巨大白カード

- 原因: デスクトップセルは素の `tk_button` で、グリッドがトラックを矩形いっぱいに
  引き伸ばすため巨大カード化していた。アイコン自体も未配線だった。
- ツールキット: `tk_button_set_icon` / `tk_button_has_icon` を追加
  （`include/tk.h`、`src/tk_widgets.c`）。ピクセルをコピー保持し、paint は
  アイコン上部中央＋ラベル下段・カード背景/枠なし・押下時のみ薄いウォッシュ。
  measure は max(テキスト幅, アイコン幅)+2*unit × アイコン高+行高+3*unit。
- Papirus 実ファイル: repo の `braindesk/assets/app/` の17枚 PNG (128×128)＋
  NOTICE (GPL-3.0) を `rebuild/assets/app/` へコピー。
- リゾルバ: `ic_resolve_icon_path` を iconcache に追加。探索順: $BD_ICON_DIR、
  assets/app、../assets/app、/usr/share/icons/brainux/app、
  $HOME/.local/share/icons/brainux/app、hicolor 48x48、Papirus 48x48/32x32、
  /usr/share/pixmaps。freedesktop 名→Papirus ステムのエイリアス表付き。
  実装中に発見したバグ（dirs[0] が getenv の NULL で NULL 終端ループが初回で
  終了）も件数ベース反復に修正済み。
- `shell/src/shellui.c`: 解決→`ic_get`(48×48)→`tk_button_set_icon`、失敗時は
  プログラム生成のプレースホルダ（48×48 の窓ピクトグラム、フォント依存なし）。
  `bd_shell_layout` は desk_grid の固定矩形を実測コンテンツサイズにクランプ。
- ラベル色: 暗い壁紙上でテーマ文字色（暗色）が読めなかったため、
  `tk_widget_set_text_color` / `tk_widget_clear_text_color`（ラベル/ボタン用
  テキスト色オーバーライド）をツールキットに追加し、シェルは壁紙の輝度
  （<128）で白ラベルを選ぶ。再撮影で判読可能になったことを確認。
- テスト: `shell/tests/test_iconcache.c` +14（実 Papirus ファイルでの解決、
  エイリアス、BD_ICON_DIR 優先、負例）。

## 項目5: レイアウトのはみ出し・切れの横断修正

### 基盤（ツールキット）側で直したもの

1. **wrap ボックスの高さ計算**（notes のツールバー欠落の真因）:
   横ボックスは子を UNLIMITED 幅で測るため、縦カラム内の wrap ツールバーが
   「1行分の高さ」で予約され、2行目が次の兄弟（エディタ）の下に描かれていた。
   `src/tk_core.c` の box arrange で、wrap 子を「実際に与えられる幅」で
   再測してから固定高に合算するよう修正（横親の flex wrap 子も同様）。
   回帰テストを test_tk3 に追加（+3）。
2. **ListView スクロールバーサム**: 内容高 > ビューポート時のみ右端 4px に
   サムを表示（ScrollView と同じ幾何、最小16px）。launcher の「スクロール
   可能と分からない」、notes のノート一覧、calc の履歴に効いた。
3. **ListView マーク行** `tk_listview_set_marked` / `tk_listview_marked`:
   選択とは別のアプリレベルハイライト（アクセントバー＋▶＋淡色背景）。
   set_items でリセット。テスト +6（test_tk3、ピクセル検証含む）。
4. **スライダつまみの右端はみ出し**: 値 1.0 でつまみが矩形の右に 7px はみ出し、
   後続ウィジェットに重なっていた（player の音量つまみが「音量 100%」ラベルに
   重なる件）。paint でクランプ。テスト追加（test_tk3）。
5. **OSK 高さフィット**（項目5の greeter/OSK 件）: `src/tk_osk.c` に
   行高フィットを追加。自然高（候補バー 40＋QWERTY 3×56＋下部バー 44 = 252）を
   維持しつつ、割り当て高が不足する場合は行を比例縮小（ヒットテストは同じ
   構築セルを使うので paint と一致）。テスト +5（osk）。480×272 の再撮影でも
   全行が収まることを確認。

### アプリ/シェル側で直したもの

- **files**: リスト/グリッドに flex=1（下半分の空白を解消）。ツールバー2行に
  `tk_box_set_wrap`（右端はみ出し→折り返し）。パス二重表示は、crumb ラベルを
  パンくず表示（「ルート › tmp › shot-files › home」、fm_crumb_* 使用）に変更。
- **notes**: フォルダ/ノート両リストに flex=1（共有高さで切れない）。
  書式ツールバーに wrap（基盤修正と合わせて チェック/添付 が2行目に表示）。
- **calc**: 履歴リストが一切描画されなかった原因は tabs/履歴とも非 flex で
  履歴が画面外に配置されていたこと → tabs flex=2、履歴 flex=1。
  キーパッドのグリッド群に flex=1（下半分の空白を解消）。「)」をグリッド内の
  最終セルへ移し、「=」を全幅キーとして独立行に（孤立配置の解消）。
- **player**: mid に flex=3、キューに flex=1（下部ボタン列の切れを解消）。
  右カラムはアートワーク＋メタ情報を横並びに再構成（縦の溢れで音量行が
  落ちていた）。再生中ハイライトは ListView マーク行で実装し、
  `sync_marked` を open_track / rebuild_rows から呼ぶ（now_path を行に照合）。
- **settings**: サイドバーで現在のページを選択状態にするよう rebuild_pages で
  同期（ハイライトなしの解消）。検索で現在のページが絞り込みから外れた場合は
  選択を明示解除 — これを怠ると古い選択が残り、次のクリックが「変化なし」で
  コールバック不発になる実バグだった（test_settings_ui の2件失敗で検出・修正）。
  編集行（スライダ/次の値/実行）は選択行の kind に応じて、PSK 行は Wi-Fi
  ページでのみ表示（`sync_editor_visibility`、切替時に再レイアウト）。
  settings_app_set_page もサイドバー同期に追随。
- **greeter**: ユーザーリストに flex=1 を与え、縦ボックスが 800×480 に
  収まるようにした（OSK 最下段の切れを解消、再撮影で確認）。
- **launcher**: アプリ/カテゴリ両リストにスクロールバーサム（基盤2）。

## 残った問題（正直なリスト）

1. **実機/QEMU ゲストでの実操作は未実施**。本フェーズの合格証拠はホスト上の
   撮影ハーネス（製品コードそのままの描画）とテストまで。SD イメージ＋
   ゲスト実操作は統合フェーズ側の残件（従来どおり）。
2. greeter のユーザーリストは flex で伸びるが、ユーザーが1名のときは
   リスト下に余白が残る（切れはしない。見た目の詰めは未実施）。
3. player のキューが空のときは空のボックスが flex 分の面積を取る。
   折りたたみ等は未実施。
4. wrap ボックスの再測は「縦親配下」と「横親の flex 子」に対応したが、
   横親配下で cross_align が STRETCH でない場合の desired 高さは
   依然 UNLIMITED 幅基準（実害のある配置は現行アプリに無し）。
5. デスクトップのプレースホルダアイコンはプログラム生成の簡易タイルのまま
   （解決できる場合は Papirus 実ファイルが使われる。解決不能ケースの
   見た目改善は未実施）。
6. フォント本体は 1.29MB。サプリメント2種（計 約57KB）が増えた。
   128MB RAM 環境でのグリフキャッシュ挙動は従来どおり（キャッシュ予算は
   既存の仕組みのまま、本フェーズでは変更なし）。
7. test_session のタイミングフレーク（上記注）は未対策。負荷下で
   pump 回数を増やす等のテスト側緩和は可能だが、今回は触っていない。
