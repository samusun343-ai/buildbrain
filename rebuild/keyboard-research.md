## 1. 結論サマリ（最重要）

PW-SH6 / PW-AJ2 の実キーボードは、**PC の JIS キーボードとは全く違う**専用キーボードである。

- 物理キー **48 個**（電源キーを含む）。数字キー列は**存在しない**。
  数字は英字キー右下の小さい添字刻印で、**［記号］キーを押しながら**英字キーを押して入力する
  （記号+Q=1、記号+W=2、… 記号+P=0）。
- **¥ キー、ろ キー、@ キー、^ キー、変換/無変換キー、半角/全角キー、英数/かなキーは存在しない。**
  記号類（@ や [ ] 等）の刻印もキー上には無い。記号入力は［記号］キー＋ソフトウェア側対応表による。
- 専用キーは辞書デバイス向け: ホーム、国語/漢字、英和/和英、My辞書、履歴、一覧から選ぶ、
  電源、シフト、ページ送り（上下2キー）、音声、記号、スペース/変換、戻る、削除/クリア、
  カーソル（上下左右）、決定。
- **音量キー・輝度キーは独立キーとして存在しない。** 音量は［シフト］+［ページ送り］の副機能
  （ページ送りキー上の枠囲み刻印）。輝度調整の物理キーは無い（設定画面で行う）。
- **一括検索の専用キーも無い。** linux-brain DTS の記号レイヤでは［記号］+［ホーム］に
  Search が割り当てられている（DTS コメント）。
- ［シフト］は WinCE 純正動作では「押して離したあと、次のキーを押す」**ワンショット式**で、
  枠囲み刻印の機能（クリア、文字小、文字大、音量大/小）を呼び出す（公式操作ガイドの記述）。
- evdev コードは PC 的な意味と**ずれた借用コード**で出る（§3 が正本）:
  ホーム=KEY_ESC、国語/漢字=KEY_TAB、英和/和英=KEY_PAGEUP、My辞書=KEY_PAGEDOWN、
  一覧から選ぶ=KEY_DELETE、履歴=KEY_INSERT、音声=KEY_LEFTALT、ページ送り（上）=KEY_LEFTCTRL。
  KEY_HOME / KEY_SEARCH / KEY_VOLUMEUP / KEY_BRIGHTNESSUP / KEY_SOUND 等は
  **このキーボードからは決して発行されない**。

| 音声 | 音声マークなどの音声を再生するときに押す |

| 戻る | 前の画面などに戻る |
| 決定 | メニュー選択や文字入力などを確定 |

| 文字小 / 文字大 | ［シフト］［◀］ / ［シフト］［▶］。文字サイズを変える（◀▶キー上の枠囲み刻印） |
| 音量大 / 音量小 | ［シフト］［ページ送り上］ / ［シフト］［ページ送り下］（ページ送りキー上の枠囲みスピーカー刻印。操作ガイドの該当箇所は図記号がテキスト抽出で欠落したが、刻印との対応からこの読み） |
| 削除 | 入力した文字を1文字ずつ削除 |

### 2.3 数字・記号の入力方式

- 数字: 英字キー右下の添字（Q=1 W=2 E=3 R=4 T=5 Y=6 U=7 I=8 O=9 P=0）が刻印で確認できる唯一の副刻印。
- 数字・記号は［記号］キーを押しながら対象キーを押す（ハードウェア＋ドライバレベルの修飾キー。
  linux-brain DTS の `symbol-key = <2 4>` がこの接点）。
- 数字以外の記号（@、[ ]、; : 等）の**キー刻印は写真では確認できない**（キー上に印字なし）。
  記号レイヤでどのキーにどの記号が割り当たるかはソフトウェア（WinCE 純正 / linux-brain）側の
  対応表で決まり、刻印からは読み取れない。linux-brain 側の割当は §3.2。
  **WinCE 純正の記号割当表が linux-brain の割当と一致するかは未確認（不明）。**

### 2.4 キー総数とマトリクス接点の対応

linux-brain DTS（§3）では 8行×7列マトリクスのうち有効な割当が **44 接点**、
コメントアウトされた位置が 3 つある: (0,3) 戻る、(0,6) Home、(3,4) PageDown。
48 物理キー = 44 有効接点 + 戻る + ページ送り（下）+ 無刻印キー候補 (0,6) + 電源（マトリクス外）と
きれいに対応する。ただし**視覚位置とマトリクス (行,列) は一致しない**（配線上の行列）。
無刻印キー（L の右）が (0,6) 接点そのものかどうかは外観からは断定できない（→ 不明事項 U3）。

## 4. PW-AJ2

- 実機写真 `keyboard-research/pw-aj2_closeup1.jpg`（正面）および拡大
  `pw-aj2_closeup1_bottom.png` / `pw-aj2_closeup1_right.png` で、**全キーの配置・刻印が
  PW-SH6 と完全に同一**であることを確認した（行1のグレーキー列、数字添字、無刻印キー、
  最下段の構成まで一致）。本体色とヒンジ部の色が違うだけである。
- 公式取扱説明書（PW-AA2/AJ2 共通、§8 [S4]）の「各部のなまえ」も同一のキー名一覧:
  ①ホーム ②コンテンツ選択 ③My辞書 ④履歴 ⑤一覧から選ぶ ⑥電源、シフト、決定、カーソル、
  ページ送り、スペース/変換、戻る、音声、記号。
- AJ2 は中学生モデル、SH6 は高校生モデル。発売は同じ 2019 年で、プラットフォームも同一系。
- linux-brain に `imx28-pwaj2.dts` は**存在しない**（確認済み・404）。参考 QEMU 実装の
  レイアウト見出しが "PW-SH6 / PW-AJ2 layout" であり、AJ2 は SH6 と同一マトリクスとして
  扱われている。AJ2 単独の DTS が無い点は未確認事項ではなく「共有扱いが現状」という事実として記す。

## 6. 現行 tk_kbd（キーボード M2）との突き合わせ差分リスト

対象: `rebuild/include/tk_kbd.h`、`rebuild/src/tk_kbd.c` の KEY_TABLE と冒頭コメント。
コードは修正していない。重大度: 高 = 実機で入力が化ける/来ない/別機能になる、
中 = 実機では起きないが前提が誤っている、低 = 命名・コメントの不一致。

### 6.1 重大（高）

| # | tk_kbd の現行 | 実機の事実 | 影響 |
|---|---|---|---|
| D1 | 数字行を PC JIS として定義（KEY_1 の JIS シフト = "!"、KEY_2 の JIS シフト = """ 等） | 数字キー自体が無い。数字は記号レイヤで KEY_1〜KEY_0 として**ドライバから直接**発行される。Shift+数字の概念は無い | 記号レイヤ経由の数字に JIS シフト刻印を適用すると誤記号になる。数字の lo/hi は US/JIS 共通で素の数字にすべき |
| D2 | KEY_YEN（¥キー）、KEY_RO（ろキー）を JIS 実キーとして定義 | **両キーとも実在しない** | 実機では永遠に来ないコード。OSK/物理の役割分担（ユーザーの「物理で打てない文字は OSK で」方針）では、¥ や ろ は OSK 側の担当であることの根拠になる |
| D3 | KEY_HENKAN（変換）、KEY_MUHENKAN（無変換）、KEY_ZENKAKUHANKAKU（半角/全角）、KEY_KATAKANAHIRAGANA を ACTION として定義 | **いずれのキーも実在しない**。変換はスペース/変換キー（KEY_SPACE）、文字切替は 記号+音声（KEY_LEFTALT、記号レイヤ） | IME トグルの物理キー前提が崩れる。変換系の操作は全てスペース/変換キーと OSK に寄せる必要がある |
| D4 | KEY_GRAVE を「JIS: 半角/全角」として IME トグルに割当 | KEY_GRAVE は**記号+D** でドライバから来る名目コード（記号入力の一環） | 記号入力のたびに IME がトグルしてしまう誤動作の種 |
| D5 | 専用キーを KEY_HOME / KEY_HOMEPAGE / KEY_SEARCH / KEY_SOUND / KEY_VOLUMEUP / KEY_VOLUMEDOWN / KEY_MUTE / KEY_BRIGHTNESSUP / KEY_BRIGHTNESSDOWN / KEY_MENU / KEY_BACK / KEY_FORWARD / KEY_POWER / KEY_SLEEP で待ち受け | **これらのコードは実キーボードから一切発行されない**（§3）。実コードは ESC/TAB/PAGEUP/PAGEDOWN/DELETE/INSERT/LEFTALT/LEFTCTRL に化けている | シェルのアクション配線が実機で全滅する。アクション判定は実コード側で行う必要がある |
| D6 | KEY_DELETE を編集キー TK_KEY_DELETE（前方削除）として定義 | 実機で KEY_DELETE を出すのは**一覧から選ぶ**キー | 一覧キーを押すと前方削除として働く誤動作 |
| D7 | KEY_INSERT を IGNORE（意図的に無視） | 実機では**履歴**キーが KEY_INSERT を出す | 履歴キーの入力が捨てられる |
| D8 | KEY_LEFTCTRL を Ctrl 修飾キーとして定義（コメント「記号キー位置」） | 実機で KEY_LEFTCTRL を出すのは**ページ送り（上）**キー | ページ送りが Ctrl 押下として解釈され、ページ送り機能が成立しない。コメントの「記号キー位置」も誤り（記号キーはイベントを出さない） |
| D9 | KEY_LEFTALT を Alt 修飾キー（コメント「文字切替」）として定義 | 実機で KEY_LEFTALT を出すのは**音声**キー（基本レイヤ）。文字切替は記号レイヤの 記号+音声 で同じく KEY_LEFTALT | 音声キーが Alt として解釈される。文字切替との区別は基本/記号レイヤの区別がドライバ内で潰れるため、evdev だけでは判別できない点に注意 |
| D10 | KEY_PAGEUP / KEY_PAGEDOWN をページ送り編集キーとして定義 | 実機では KEY_PAGEUP=**英和/和英**、KEY_PAGEDOWN=**My辞書** | 辞書キーがページ移動として働く誤動作（tk_kbd.c コメントの「ページ送り are real PageUp/PageDown」は誤り） |
| D11 | KEY_ESC を「調べる」として TK_KEY_ESCAPE に定義 | 実機で KEY_ESC を出すのは**ホーム**キー | 命名の誤りだけでなく、ホーム＝シェルのホームアクションとして扱うべき入力が Esc として流れる |
| D12 | 記号類を PC JIS 刻印で定義（KEY_LEFTBRACE JIS="@"、KEY_EQUAL JIS="^"、KEY_SEMICOLON JIS="+"、KEY_APOSTROPHE JIS=":"、KEY_BACKSLASH JIS="]" 等） | これらのコードは**記号レイヤの名目コード**として来る（記号+K=LEFTBRACE 等）。実機に @ キー・^ キーは無い。どの記号文字になるかは刻印ではなくソフトウェア対応表の領分で、現行の JIS 刻印写像は無根拠 | 記号入力の出力文字が実機の期待と一致する保証が無い。記号レイヤの文字割当は別途「記号対応表」として定義すべきで、PC JIS 刻印表を流用してはいけない |

### 6.2 中

| # | tk_kbd の現行 | 実機の事実 |
|---|---|---|
| D13 | 冒頭コメント「46 keys, JIS arrangement」「driver is sharp,brain-kbd-i2c」 | 物理キーは 48。DTS 上の有効接点は 44（+コメントアウト3）。ドライバは GPIO マトリクス（keyboard_gpio）で、I2C ではない（buildbrain 側フォークの実態は未確認 → U4）。「JIS arrangement」は誤解を招く（数字・記号の入り方が JIS と無関係） |
| D14 | KEY_TAB を TK_KEY_TAB（フォーカス移動）としつつ「国語辞典ボタン」と注記 | 注記自体は正しい（国語/漢字=KEY_TAB）。ただし Tab として素通しすると辞書キーとフォーカス移動が混線する。シェル/アプリ側で文脈分離が必要という設計論点 |
| D15 | シフトを「押している間」の修飾キーとして処理 | WinCE 純正はワンショット（押して離す→次の1キーに効く）。Brainux（evdev）では KEY_LEFTSHIFT の押下/解放がそのまま来るので保持式でも動くが、枠囲み機能（クリア=Shift+削除、文字小/大=Shift+◀/▶、音量=Shift+ページ送り）の割当自体が tk_kbd に無い。特に音量は Shift+KEY_LEFTCTRL という和音になる |
| D16 | KEY_CAPSLOCK の状態管理 | 実キーボードに Caps キーは無い（PC キーボード併用時のためのものとして残すなら、その旨を明記すべき） |
| D17 | KEY_END を編集キーとして定義 | 実キーボードから KEY_END は来ない（行末キーは無い） |
| D18 | 戻るキーの扱いが無い（KEY_BACK は来ない前提のまま） | 戻るは接点 (0,3) に実在するが現行 DTS でコメントアウト＝イベントが出ない。直すなら DTS 側（ドライバ）でコードを割り当てる話であり、tk_kbd 側だけでは解決しない |

### 6.3 低（命名・コメント）

| # | 内容 |

| D20 | KEY_MINUS: 実刻印は「ー」（長音）。JIS シフトで "=" を出す現行写像は PC JIS 由来で実機根拠なし（記号レイヤでは 記号+ー=KEY_SLASH） |

## 7. 本調査の方法メモ

- 刻印・配置は実機写真2機種分を目視で読み取り、拡大クロップで最下段と右端を再確認した。
- キー機能の名称は公式操作ガイド/取扱説明書の「各部のなまえ」で照合した。
- evdev コードは linux-brain の imx28-pwsh6.dts を正本とし、参考 QEMU の brain-kbd.c と突き合わせた
  （両者は一致。ただし QEMU 側はホスト PC キー→接点の写像であり、記号割当はホスト都合のものを含む）。
