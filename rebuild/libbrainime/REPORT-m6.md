## 1. 前任の意図の復元（復元した前提）

前任は報告を残さなかったが、作業物は完備していた。以下は全て実測で裏付けた。

### 1.1 BIGR 再抽出（extract_bigram_m6.py / extract.log）

- 抽出元コーパスは合計 **65,000文**: M3 の 19,987文 + M5 の新規ペア 40,000件の
  原文 37,999文（dev_big 2,000文を除外して計数）+ 継続スキャンで得た新規 7,014文。
- 漏洩ガードは M5 と同型: 除外 gold 4,610件、dev_big は計数から除外。
- 閾値 count>=3 で **29,982 対**（distinct は 140,402、>=2 は 48,778）。
  BIGR 節は 262,152 B → 524,296 B（スロット 32,768 → 65,536）。
- 全候補辞書で DICT/TOKID/CLSREP/CONN/SUPP 節の CRC は現行（M5）と完全一致し、
  差分は BIGR・RNK・META のみであることをセクション単位で確認した。

### 1.2 候補辞書の正体（セクション CRC と重みファイルの照合で同定）

| ファイル | feat | RNK の中身 | 正体 |
|---|---|---|---|
| brainux3-v1.bid3 | 3 / 26 | 初期重み（w0=1 のみ） | 新 BIGR + 未学習 |
| brainux3-v1t.bid3 | 3 / 26 | train_v1 最終平均重み | **v1 の学習済み版（採用）** |
| brainux3-v4.bid3 | 4 / 28 | 初期重み | feat v4 コード + 新 BIGR + 未学習 |
| brainux3-v4e1.bid3 | 4 / 28 | v4 学習 epoch 1 の ckpt 重み | v4 の学習途中版 |

- w_v1.bin は v1t の RNK と float 単位で完全一致し、train_v1.log の
  「weights (averaged)」印字とも一致 → v1 の学習は 3エポック完走していた。
- w_v4.bin は v4e1 の RNK と完全一致 → v4e1 = epoch 1 チェックポイント。
- **ab ファイルの「v1」は v1t のこと**: 未学習 v1.bid3 を dev500 で測ると
  48.4% で ab_v1_dev500（54.4%）と合わず、v1t では 54.4% に完全一致した。
- **ab_v4e1_dev_big（57.4%）は v4 ビルドの bi で測られていた**: 締め作業で
  再測定し、v4/tools/bi では 1148/2000 = 57.4% に完全一致、本ツリーの
  tools/bi では 46.9%（feat_ver 4 を版ゲートが弾きリランカー無効 = Viterbi 順
  そのまま）になることを確認した。前任の測定は正しい測定器で行われていた。

### 1.3 feat v4（表記条件つき bigram 特徴）

m6work/v4/ は本ツリーの複製に以下の差分を入れた実験ツリーだった
（diff で全量確認）:

- `BI_RERANK_NFEAT` 26 → 28、feat_ver 4。追加特徴は M5 §5.5 の
  「表記選択の差 144件」を狙ったもの:
  - 特徴26: 現在の文節の表記が読みのカタカナ形である bigram 証拠の和
  - 特徴27: 現在の文節がかな同一（表記 == 読み）である bigram 証拠の和
- dict.c の版ゲートを 1..4 に拡張、build_bidict3.py / patch_rerank.py の
  FEAT_VER を 4 に追随。それ以外のエンジン差分はこの特徴計算のみ。

### 1.4 v4 学習の停止位置

- train_v4.log は epoch 1 の ckpt（dev 58.7%）で止まっており、学習は未完だった。
- train_v4b.log（見出し行のみ、29 B）は 03:34 に開始された2回目の実行が
  epoch 1 を終える前に終了した痕跡と推定する（v4e1.bid3 の生成と同時刻）。
  ※この1点は時刻と内容からの推定であり、断定ではない。

## 2. v4 学習の完走（締め作業で実施）

チェックポイント版 trainer（m6work/v4/train_rerank_ck）で
brainux3-v4.bid3 + train_m5（42,650行）+ dev_big を最初から3エポック実行した
（m6work/train_v4full.log、重みは m6work/w_v4full.bin）。

- **決定性の再現確認**: epoch 1 の結果が前任の train_v4.log と完全一致
  （train top-1 53.2%、更新 13,364回、ckpt dev 58.7%）し、epoch 1 時点の
  チェックポイント重みは w_v4.bin とバイト単位で一致した。
  §1 の復元（学習データ・辞書・trainer の同一性）が正しいことの実証になる。
- epoch 2: train 53.3%、ckpt dev 58.5%。epoch 3: train 53.2%、ckpt dev 58.6%。
  trainer 内 dev（dev_big、collect ベース評価）は epoch 1 が最良で横ばい。
- 最終平均重みで brainux3-v4f.bid3 を構築した（特徴26 = −4.8776、
  特徴27 = +0.9905。表記特徴はゼロでない重みを獲得した）。

### 3.1 ペア比較（McNemar、同一文での勝敗入れ替わり）

ab ダンプの FAIL 一覧から文単位で照合した（単独比率の標準誤差 ~1.1pt より
ペア比較の方がこの判断には適切）:

| 比較 | dev_big 勝/負 | net | χ² | p（近似） |
|---|---|---|---|---|
| M5 → v1t | 47 / 26 | +21 | 6.0 | ≈0.014 |
| M5 → v4e1 | 51 / 25 | +26 | 8.9 | ≈0.003 |
| M5 → v4f | 50 / 26 | +24 | 7.6 | ≈0.006 |
| v1t → v4e1 | 16 / 11 | +5 | 0.9 | ≈0.34 |

dev500 では v1t が net −2（6勝8敗）、v4f が net −3（4勝7敗）で、
500件規模のノイズ範囲内。手作り tuning は全候補同点（50/58）。

## 4. 採否と根拠

- **v1t を採用**: dev_big で M5 をペア比較で有意に上回り（p≈0.014）、
  dev500・tuning に有意な悪化なし。変更は辞書ファイルのみで、
  エンジンコード・特徴量版は不変（ロールバックも M5 辞書の複写で済む。
  M5 辞書は m6work/brainux3-m5.bid3 に保存した）。
- **v4（feat_ver 4）は不採用**: 表記特徴は v1t に対して有意な上積みが
  なかった（dev_big net +5、p≈0.34、他セットは同点）。一方で採用には
  エンジン本体（engine.c / dict.c / bi_internal.h）と builder / patch
  スクリプトの版上げを本ツリーへ取り込む必要があり、測定上の利益なしに
  コード変更のリスクだけが残る。M6 のレバー(2)「表記選択のモデル化」は、
  線形特徴2個の追加では不十分という結論になった。実験ツリーと重みは
  m6work/v4/・w_v4.bin・w_v4full.bin に残置する。
- 改善の主因はレバー(1) BIGR 再抽出（18,738 → 29,982 対）であり、
  3候補とも同じ BIGR を持ち、差は重みと特徴だけであることと整合する。

### 5.2 held-out 最終採点（1回のみ、単一パス）

| 項目 | M5 | M6 |
|---|---|---|
| top-1 | 283 (57.3%) | **285 (57.7%)** |
| n-best@8 | 406 (82.2%) | **407 (82.4%)** |
| n-best@16 | 419 (84.8%) | 419 (84.8%) |

dev 合算の推定（+0.8 pt）より小幅だが方向は一致し、held-out 固有の
過学習の兆候はない。

### 5.3 bench（494 readings × 20 iter、dev_big の読みを使用）

同セッション A/B（本セッションのホストは他作業と競合しており絶対値は
M5 レポートの 8.20 ms と比較できない。相対比較のみ）:
M6 平均 9.857 ms / RSS 13,316 kB、M5 平均 11.245 ms / RSS 12,788 kB。
RSS は BIGR スロット倍増で触れるページが増えた分 +528 kB
（M5 が自らに課した目安 +1 MB 以内）。平均変換は測定順と競合の影響が
大きく、「改善した」とは主張しない。悪化の証拠もない。
ロード時間は単発値が競合で振れるため（本セッション実測 14.9 ms /
59.5 ms と順序で逆転）M5 の遅延 CRC 経路のまま据え置く。

## 6. ボトルネック内訳の更新（held-out ミス 209件、ダンプからの事後分類）

| 分類 | M5（ミス211） | M6（ミス209） |
|---|---|---|
| n-best@16 内にあるが top-1 でない（順位負け） | 136 | **134** |
| n-best@16 に無い | 75（プール外@64 の 65 + プール内@16外 10） | **75** |
| 文節候補から組み立て不能（辞書・分割の欠落） | 36 | **34** |
| （重複集計）表記選択の差: カナ表記を畳むと正解と一致する表記が n-best 内に存在 | 144 (68%) | **142 (68%)** |

- 内訳の構造はほぼ不変。BIGR 増強は順位負け・組み立て不能を僅かに減らしたが、
  最大分類の「表記選択の差 68%」は手つかずに近い。
- 表記選択は文脈依存性が高く（ユミコ/ゆみこ、キレイ/きれい のどちらが正解かは
  文と書き手の習慣で決まる）、feat v4 の線形特徴2個では捉えきれなかった（§4）。
  次に試すなら、表記形そのものの頻度 prior（単語コスト側への表記嗜好の
  織り込み）か、bigram の表記ペア単位の証拠（現行は文節単位の集計）が候補。
  ただし held-out の正解表記自体が書き手依存である以上、この分類には
  原理的に回収不能な分が含まれる点は M5 から変わらない。
