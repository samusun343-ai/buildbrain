# libbrainime M1 レポート

新規作成した日本語変換エンジン (lattice + Viterbi) の初回実測。
**結論を先に: 変換品質はまだ実用水準ではない。** 回帰コーパス
top-1 一致率は 34.5% (20/58)。エンジンの骨格 (辞書ロード、
lattice、Viterbi、n-best、文節操作、セッション API) は動作し、
辞書引きは元の実装と完全一致するが、コストモデルの粒度不足が
品質の上限になっている。以下、数字と失敗分類を正直に記録する。

## 検証結果

### 辞書引き等価性: 15/15 完全一致

元の `bidict_lookup2` と同一の候補列を返すことを 15 読みで確認
(あ / かんじ / とうきょう / ました / を / です / がっこう /
にほんご / たべる / ん 等)。辞書ロード層は正しい。

### セッション API: 16/16 PASS

変換 → 候補選択 (再変換なし) → 文節伸縮 (resize) → 先頭文節の
確定と継続 (commit_first) → 強制境界変換、の一連を検証した。

### 変換コーパス: top-1 一致 20/58 = 34.5%

- 失敗 38 件中、期待文が n-best 内に存在: 12 件。
- 失敗 38 件中、文節候補から期待文を組み立て可能: 19 件
  (check.py の貪欲最長一致による緩い指標。鵜呑みにしないこと)。
- **正直な留保: このコーパスは M1 の調整にも使ったため held-out
  ではない。** 未知文での実力はこれより低い可能性がある。
  held-out 評価セットの構築は M2 の必須作業。
- 単体では正解する語が文中で崩れる例が複数ある (えいご→英語、
  しんぶん→新聞、かぞく→家族 は単独では正解、文中では失敗)。
  文脈を使う仕組み (単語 bigram / 語彙化接続) の欠如が主因。

### 失敗分類 (38 件、主因ベース)

| 分類 | 件数 | 代表例 |
|---|---:|---|
| コストモデル | 22 | てんき→点期、にわ→二輪、かいもの→かい者、かいました→書いました、すし→すし (寿司でない)、こと→コト、しゅと→種と、です→出す |
| 文節分割 | 14 | でんしゃ→出ん者、でんき→出んき、この→子+の、しごと→し毎、どのくらい→土の喰らい、うんてん→生んてん |
| 辞書不足・活用合成 | 2 | すんでいます (連濁形の合成なし)、きていません (来て の合成負け) |

分類上の注意: 文節分割の失敗の大半も根本はコストであり
(正しい長いノードは lattice に存在するが総コストで負ける)、
両分類は重なる。純粋な辞書不足が少ないのは mozc 由来 18 万
エントリの網羅性による。一方で活用形は辞書にほぼ無く
(かきました等は未登録)、語幹+助動詞の合成に依存するため、
活用が絡む文は構造的に弱い。また mozc データ由来の姓の別読み
(ました→増田/益田 等) のような「辞書にはあるが文脈で抑える
べき」候補も、文脈モデルが無い現状では抑えきれない。

### 棄却した調整実験 (再試行しないこと)

- 助動詞クラスへの接続を動詞と同型に扱う案: 13/58 に悪化、撤回。
- 助詞→連用形ペナルティ (右読み末尾のかな行で判定): A/B で
  基準 19/58 → 18/58、改善ゼロで別の文を壊したため撤回
  (conn.c に記録)。
- 文節数ペナルティ掃引 (260/340/420/500): ほぼ無変化。既定 260。

## 性能 (ホスト実測)

計測環境: 共有 VM (1.5 vCPU)、辞書 brainux2.bidf。

| 項目 | 実測 |
|---|---:|
| 辞書ロード | 12.0–12.3 ms (3 回) |
| 変換 1 回 (コーパス 58 読み × 50 回 = 2900 回の平均) | 2.757 ms |
| ピーク RSS (bench プロセス VmHWM) | 6064 kB |

- RSS には触れた mmap 共有ページが含まれる。匿名の常駐分は
  トークン索引 約 1.1 MB + lattice 作業領域 (文長依存、通常
  数十 KB) が中心で、辞書本体は共有 mmap のためプロセス固有の
  常駐にはならない設計。
- **ARM 換算の注意: PW-SH6 (i.MX283、単コア・低クロック) では
  1 桁〜2 桁遅くなる前提。** 変換 2.8 ms (ホスト) が実機で
  数十 ms 級になっても OSK の応答性としては許容圏だが、
  これは推測であり、ゲスト実測は M2 の合格条件。

## 既知の制限 (M2 へ)

1. 接続モデルが 52 クラス (mozc は 3,019 の語彙化クラス)。
   単語 bigram が無い。品質改善の本丸はここ。
2. 辞書の conn 部が全ゼロで出荷されている。辞書生成側で実
   マトリクスを持てるようになれば `conn_from_dict=1` で
   自動的にそちらを優先する実装にしてある。
3. 連濁 (すむ→すんで) 等の音便・連濁の合成規則が無い。
4. 学習機能なし (ユーザー辞書・変換履歴の反映は未実装)。
5. セッション: 確定後の残りが助詞始まりだと変換が劣化する
   (左文脈の引き継ぎが必要)。
6. held-out 評価セットが無い。コーパス自体の拡充 (固有名詞・
   同音異義・長文) と合わせて M2 で構築する。
