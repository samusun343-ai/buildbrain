## 1. 介入A: 欠落エントリの SUPP 追加

対象は M10 §1.4 が同定した欠落 43 ペアから、Sudachi の語幹分割
由来の断片 4 件（よみ→読、やけ→焼、や→家、こみあっ→こみ合っ）
を除いた **39 件**（おいで→御出で、ひらべ→平部 は境界例だが
M10 の「実質約 39 件」の数え方に従い含める）。

コストバイトの校正（根拠）:

- 既存 SUPP の価格スケールは出自で二層ある: neologd 35,000 件は
  全て byte 15（百分位正規化の下限張り付き、M4 で権威マージン
  問題を起こした側）、sudachi 116 件は byte 115–196（中央値 196、
  式は 240 − 28·log2(コーパス頻度 n)）。
- 今回の 39 件のコーパス頻度は 27 件が n=0、残りも n≤2 で、
  頻度式は 212–240 に飽和し実質無情報。
- **同一操作の実測前例が M4 にある**: SudachiDict 普通名詞の
  手動追加 4 件（苛々/継母/帳尻/トンボ返り）は **cls=1・byte=180**
  で投入され、2 件が top-1 回復・回帰なしだった。
- DICT（mozc）側の漢字複合語バイトは中央値 111（p25–p75 =
  100–118）と SUPP sudachi 帯より安いが、SUPP レコードとして
  競争する以上、同じ SUPP 帯・同じ操作の前例に合わせるのが
  一貫する。**全 39 件を cls=1・byte=180・source=sudachi で
  投入する**（M4 前例の完全な踏襲。byte は sudachi 分布
  115–196 の内側）。

生成: m11work/supp_a.tsv = m3work/supp.tsv + 39 行（既存との
重複は生成時に検査、全件新規であることを確認）。

## 2. 介入B: かな形エントリ（相対価格介入）

### 2.0 前提の訂正（M10 §1.3 の special 統計は artifact）

B の同定作業中に、M10 §1.3 の中核的主張「D の正体は未知語価格の
割高さ（gold の未知語支払い中央値 5,840）」が**計器の読み違い**
であることが判明した。vgold の golddecomp 行は最終状態の走査中に
答えが改善されるたびに出力され（121 件中 98 件が複数行）、
§1.3 の special 統計（中央値 5,840 / 平均 4,608 / ゼロ 26 件）は
**各ケースの最初の行**の値と完全一致する。最小コストパスの分解
である最後の行で再計算すると:

| 統計量 | M10 §1.3（最初の行） | 訂正値（最後の行＝最小コストパス） |
|---|---|---|
| special 中央値 | 5,840 | **0** |
| special 平均 | 4,608 | **545** |
| special = 0 の件数 | 26 / 121 | **101 / 121** |

なお §1.3 の word/conn 分解（Δword 中央値 +1,136 が支配成分）と
d_decomp.json の三つ組は最後の行と全件一致しており正しい。
壊れていたのは special の内訳解釈のみ。訂正後の分解
（gold 最小コストパス − エンジン最良パス、BI_TRACE 併用）:

- Δword 中央値 +1,136 のうち special の寄与は中央値 0。
  special を除いた辞書単語だけの Δ は中央値 **+784** —
  つまり D は「gold の辞書単語列そのものが最良パスより高く、
  セグメント数も中央値 +1 個多い」という通常の単語コスト競争
  であり、未知語課金は支配的メカニズムではない。
- M10 §2 の vsp 実験が D を 0 件しか回収できなかった事実は、
  この訂正と整合する（未知語価格は元々ボトルネックでは
  なかった）。M10 §2 の測定値自体は直接測定であり有効。

このため **B が届く範囲は「最小コスト gold パスに未知語かな
span が実在するケース」に限られ、その数は 10 件**（下記）。
B は課題どおり実施するが、期待効果の上限は dev 合議で
最大 +10 件程度と見積もるのが正直なところである。

## 4. 判定: A+B を採用

根拠: A+B は合議最大（+19）、dev_big で有意（χ²=12.07 ≥ 3.84）、
悪化 0 件、サイズ増は +968 B（+0.012%）。B 単独では有意でない
（χ²=0.00）が、バンドル内では dev_big +1 / dev500 +2 を悪化なしで
上乗せしており、除外する理由はない。A 単独採用（+16）より
A+B の方が全指標で上である。

反映:
- m11work/dict_ab.bid3 を data/brainux3.bid3 へ配置
  （8,198,336 B、md5 86c681403b67af4c854a7e7eaa6eeb1e、
  cmp でバイト一致を確認）。
- 追加 49 行を m3work/supp.tsv へも追記し、将来の再生成が
  採用辞書を再現するようにした（m3work/supp.tsv は
  m11work/supp_ab.tsv とファイル同一になったことを diff で確認）。

held-out 494 文（m3work/corpus/eval_pairs.tsv、m5work/eval_once.py
で単一パス 1 回だけ採点、ダンプ m11work/heldout_dump_m11.jsonl）:

| | top-1 | n-best@8 | n-best@16 |
|---|---|---|---|
| 旧（M7） | 290 (58.7%) | — | 428 (86.6%) |
| 新（M11 採用） | **290 (58.7%)** | 414 (83.8%) | 428 (86.6%) |

ダンプ同士の比較では held-out 上の反転は **得 0 / 失 0**。
正直な評価: dev の改善は held-out に転移しなかった。A の
エントリは dev のエラーから掘り起こした稀少語であり、dev での
+16 にはその選択効果が含まれる。held-out が悪化しなかった
ことは「一般語彙の穴埋めとして無害」までは示すが、汎化した
改善としては主張しない。held-out top-1 は **58.7% のまま**
（目標 60% 未達も変わらない）。

回帰確認（採用辞書で実施）:
- make test: exit 0（session_test PASS）
- make test3: exit 0。sentences 51/58 = 87.9%、
  tests/heldout.tsv（手作り）46/58 = 79.3%（いずれも M7 と同値）、
  crc_test 0 failures
- 変換遅延: エンジン無変更・SUPP +49 件のみ。ホスト実測の
  mean は実行ごとに 6.5–16 ms とばらつきが大きく（旧辞書でも
  同範囲）、構造的な悪化はない

計器に関する注意（将来の参照用）: `bi eval tests/heldout.tsv`
は旧・新どちらの辞書でも top-1 0% を返す（ファイル先頭の
コメント行との相互作用と思われる）。このファイルの正規の
採点は tests/check.py（test3）であり 79.3% が実値。dev 系
ファイルでは bi eval は正常で、§0・§3 の数値は全て同一計器の
相対比較である。

## 5. M10 への訂正の要約（§2.0 の再掲）

M10 §1.3 の「D の正体は未知語価格の割高さ（gold の未知語支払い
中央値 5,840）」は、golddecomp の**最初の行**（最小コストパス
ではない）を読んだ artifact であった。最小コストパスでは
special 中央値 0（101/121 件がゼロ）であり、D の実像は
Δword 中央値 +1,136（辞書単語同士の競争、special 寄与は
中央値 0）＋ Δseg 中央値 +1 本の通常のコスト競争である。
M10 の §1.4（A の同定）・§2（vsp 等の実験値）・§1.3 の
word/conn 分解自体は最後の行と一致しており有効。この訂正に
より「未知語価格」を対象とする将来の介入は根拠を失う;
残る D 121 件への処方箋は、辞書単語コストの相対校正
（M9 で頭打ちが示された頻度系とは別の信号）か、接続コスト
側の再検討になるが、いずれも今回の範囲外。
