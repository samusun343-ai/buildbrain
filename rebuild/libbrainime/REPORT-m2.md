# libbrainime M2 レポート — 語彙化接続コストと変換品質

## 結論 (held-out で主張する)

未使用の評価セット (held-out 58 文) で、変換 top-1 一致率は
**M1: 13/58 = 22.4% → M2: 39/58 = 67.2%** (3.0 倍)。
n-best 内包率 (top-1 + 失敗分のうち期待文が n-best に在る割合)
は **43.1% → 93.1%**。調整に使った M1 コーパス (58 文) では
34.5% → 81.0% だが、こちらは調整バイアスを含む参考値であり、
改善の主張は held-out の数字に基づく。held-out の方が低い
(67.2% vs 81.0%) のは調整コーパスの楽観であり、そのまま記録する。

| コーパス | エンジン | top-1 | n-best 内包 |
|---|---|---|---|
| 調整 58 文 | M1 | 20/58 = 34.5% | 32/58 = 55.2% |
| 調整 58 文 | M2 | 47/58 = 81.0% | 55/58 = 94.8% |
| **held-out 58 文** | M1 | **13/58 = 22.4%** | **25/58 = 43.1%** |
| **held-out 58 文** | M2 | **39/58 = 67.2%** | **54/58 = 93.1%** |

held-out は `tests/heldout.tsv` (日常/仕事/学校/旅行/同音異義/
固有名詞/て形/混在の 58 文)。M2 の調整は全て調整コーパスと
個別プローブでのみ行い、held-out は既定値を凍結した後に
1 回だけ採点した。

## 1. データ入手元とライセンス

接続コストの源泉は mozc の公開データ。

- 入手元: https://github.com/google/mozc 、
  コミット `3cf2d38553835f9241479d3b42c7d408c8f45076`
  (2026-11-20 取得。BIDF 辞書を生成した
  `buildbrain/tools/ime/convert_mozc.py` + `MOZC-NOTICE.md`
  が記録していたのと同一スナップショット)
- 使用ファイル: `src/data/dictionary_oss/` の
  `dictionary00.txt`〜`dictionary09.txt`、`id.def`、
  `connection_single_column.txt`
  (sha256: connection = `68823a1f6617372ccb89afdbcb334d7a0bcfa82c9c5dda03fc1f80f1cab5c48e`,
  id.def = `07a05a268c3783b7e02b36e4aa591555a2dd19a1f3c93891576740761c154f2d`)
- ライセンス: mozc 本体は BSD-3-Clause。辞書データは
  IPADIC 由来 (NAIST 辞書利用条件、ICOT 条項を含む) と
  沖縄辞書 (public domain) を含む。全文は
  `buildbrain/tools/ime/MOZC-NOTICE.md` に既存の記録がある。
- 接続行列の形式: 先頭行 `2672` (ID 数)、続く 7,139,584 値が
  row-major で `index = rid(左) × 2672 + lid(右)`。これは
  mozc 本体の `src/data_manager/connection_file_reader.h` の
  読み出し規約で確認した。生コスト範囲 0..15281。

作業用の mozc クローン (113 MB) は生成後に削除した。再生成は
上記コミットから `tools/gen_sidecar.py --mozc-dir` で可能。
成果物は `data/brainux2.bisc` (7,860,672 バイト) のみ。

## 2. ID 対応付けの方法 (BIDF エントリ ↔ mozc ID)

BIDF v2 のエントリは (読み, 表記, 品詞クラス 0..255, コスト
バイト) しか持たず、mozc の lid/rid を持たない。そこで
`tools/gen_sidecar.py` が BIDF 生成時の dedup を再演する:

1. BIDF の全トークンを格納順に列挙する (純 Python の BIDF
   リーダで読み出す)。
2. mozc 生エントリを (読み, 表記, classify(lid)) でグループ化
   する。`classify` は `convert_mozc.py` の関数をそのまま使い、
   AST 比較で原文と一致することを確認した (転記ミス 1 件 —
   「副助詞／並立助詞／終助詞」を「副詞／…」と写し間違え、
   14 トークンが未対応になっていた — を検出・修正済み)。
3. 各トークンについて、同グループの最小コストエントリを
   源泉とし、その mozc コストを BIDF の量子化式
   (byte = cost × 255 / 11895、11895 は dedup 後コストの
   p99 で原文と再計算一致) で再量子化し、トークンのコスト
   バイトと一致することを検証する。

結果: **180,000 / 180,000 件が対応し、コストバイト検証も
全件一致。未対応 0 件。** 複数の異なる lid を含む曖昧な
グループは 15,280 件あったが、dedup の規則 (最小コスト)
により源泉は一意に定まる。ただし最小コスト同点で lid が
割れるグループが 294 件あり、ここだけ統計で決めた:

- 失敗した方式 (実測): 行列の行平均+列平均 → 「まし」の
  特殊・マス命令形 (lid 234) を選んで 〜ました が全滅した。
  辞書出現数による頻度重み → 助動詞・助詞は辞書出現数が
  少なすぎ、同じく 234 を選んだ。
- 採用: **列平均 (lid) + 行 25 パーセンタイル (rid)**。
  語幹のような ID は「少数の後続にだけ安く付く」ため行平均
  が不当に悪くなる。列側は実績が素直に出る (まし: 列平均
  6383 vs 7797、実接続 1402 vs 9193)。

.bisc には他に、未知ノード・特殊ノード用のクラス代表
(クラス毎の最頻 lid/rid) と、行列を /64 に量子化した
u8[2672×2672] を格納する。実行時は辞書と並べて mmap し、
接続コスト = 格納値 × 64 × scale/1000 (scale 既定 200) で
引く。BOS は rid 0、EOS は lid 0。サイドカー有効時は
conn.c の 52 クラスのルールモデルと form_adjust を丸ごと
バイパスする (単語コスト側の surface_penalty は併用)。

## 3. その他の M2 実装

- **音便合成** (`add_onbin_virtuals`): BIDF に音便語幹が
  無い五段連用が約 1,047 組ある。促音便 (っ) / 撥音便 (ん)
  は語幹末尾が変わるため lattice 上のノードからは合成
  できない (入力 かって に対し かい はマッチしない)。入力中
  の っ/ん+て/た (で/だ) から候補の連用読みを復元して完全
  一致検索し、語幹+て/た を 1 ノードで合成する (ペナルティ
  既定 400)。検証プローブ: 辞書に語幹が無い うれった →
  憂った が単一ノードで生成され、合成を無効化すると
  売れった に劣化することを確認。イ音便・サ行は語幹が
  そのまま合成でき、連濁は読み自体が辞書にあるため対象外。
- **セッション左文脈**: `bi_session_commit_first` が確定
  文節の品詞・lid/rid を保持し、残りの再変換で文頭接続を
  BOS でなくその文脈から計算する。M1 の劣化例
  (手紙を確定した残り をかきました → ヲか気ました) は
  を書きました に修正された (テストで固定)。
- **resize の no-cut zone**: 強制境界だけでは文節内部の
  区切りを防げないため、resize 対象文節の区間内に開始/
  終了するノードを禁止し、文節が指定長 1 ノードになる
  ことを保証する (M2 のコストモデルで露見した回帰の修正)。
- **学習 (最小実装)**: `bi_engine_enable_learning(e, path)`。
  確定毎に (読み, 表記) を数えて TSV へ即時永続化し、
  変換時に単語コストから 1 回 100・上限 1000 を引く。
  テスト: かみ の候補 髪 を 6 回確定すると、履歴ファイル
  だけを共有する別エンジンで top-1 が 髪 に反転する。
- fcitx5 アドオンは M2 対象外 (DESIGN.md のメモ更新のみ)。

## 4. 失敗分類の変化 (調整コーパス、M1 分類との対比)

M1 の 38 件は コストモデル 22 / 文節分割 14 / 辞書不足・
活用合成 2 だった。M2 の失敗は 11 件:

- コスト残差 (同音異義・語彙選択の僅差) 7 件: いい→良い、
  機能 vs 昨日 (2 件)、町 vs 街、朝ご飯→あさごはん、
  行く vs 行う (行いたがって)、1234 園 vs 円。
  いずれも期待文は n-best 内 (8/11) にあり、破綻型ではない。
- 文節分割 3 件: かばん→か版、しないで→市内で、
  てがみが→手が磨きました。
- 合成・辞書構成 1 件: きていません→来て今線
  (〜ていません の構成が弱い)。

held-out の失敗 19 件も同型で、15 件は期待文が n-best 内。
n-best に無い 4 件は 風邪をひいて (風+引いて の分割)、
持ってい無い (いない の構成)、六時→置きます (数詞文脈の
おき)、朝ごはん (語彙選択)。文頭助詞の劣化や
ヲか気ました 型の破綻は両コーパスから消えた。

残る構造的な天井: 機能/昨日 のような mozc データ自体が
僅差の組 (単語コスト・接続とも互角) は、単語 bigram や
文脈モデルが無い限り覆せない。これは M1 の「52 クラス」
より遥かに高い位置にある天井だが、天井であることは
変わらない。

## 5. 性能 (ホスト実測、65 読み × 50 回、同一条件で対測)

| | ロード | 変換平均 | ピーク RSS |
|---|---|---|---|
| M1 | 44.7 ms | 5.474 ms | 6,160 kB |
| M2 | 12.0 ms | 5.239 ms | 12,644 kB |

変換平均は悪化なし (行列引きは O(1)、ルールモデルの計算が
消える分むしろ同等)。ロード時間はページキャッシュで
変動が大きく (M1 レポート時は約 12 ms)、絶対値より
「桁は変わらない」程度に読むべき数字。RSS の +6.5 MB は
行列ページ (7.1 MB) の常駐分で、128 MB の予算に対しては
許容範囲だが無視できる量ではない。辞書ロード自体は
mmap ゼロコピーのまま。ARM (i.MX283) のゲスト実測は
M1 から引き続き未実施で、合格条件として残る。
