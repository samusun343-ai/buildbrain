仕様確認（Web・一次ソース、2026-11-20 取得）:

- **Radio の矢印キー**: Microsoft Learn「Guidelines for
  radio buttons」の "Selection follows focus" 節 —
  グループ内では矢印キーで項目間を移動し、フォーカスが
  移った項目が選択される。Ctrl+矢印は選択を変えずに
  フォーカスだけを移し、Space で選択する。RadioButtons
  グループは端でラップしない。現行実装は Space のみで
  矢印キーが無く、両モード共通の欠落 → **実装する**。
- **Slider のキー**: M3 sliders accessibility
  （m3.material.io）— Tab でハンドルへ、矢印で 1 目盛、
  Home/End で最初/最後の値。APG slider パターンと
  WinUI の慣行では PageUp/PageDown = 大ステップ
  （LargeChange、矢印ステップの 10 倍が既定の対応）。
  現行実装は Left/Right のみで Up/Down・Home/End・
  Page 系が無い → **実装する**（Up/Down は APG/WinUI
  とも増加/減少に含まれる）。
- **Segmented（複数選択）のキー**: 単一選択形は矢印で
  選択移動が実装済み。複数選択形にはキー処理自体が
  無い。WinUI の ToggleButton 群（各々がタブストップ）
  と APG のツールバー型（矢印で移動、Space で切替）を
  単一ストップに写像し、矢印でカーソル移動・Space/
  Enter で切替として **実装する**。

実装予定（いずれも両モード共通コード）:
1. Radio: 矢印キーで同一親・同一グループ内の前後へ
   フォーカス移動＋選択追随（端で停止、無効はスキップ）。
   Ctrl+矢印はフォーカスのみ。
2. Slider: Up/Down/Home/End/PageUp/PageDown を追加
   （単一・Range・デュアルの各形、アクティブハンドル
   に対して作用し相手ハンドルでクランプ）。
3. Segmented（複数選択）: 矢印カーソル＋Space/Enter
   切替、フォーカス中はカーソルセグメントに状態層。

   修正: 表示時に直前のフォーカスを保存し
   （menu/dialog の focus_return）、オーバーレイ除去時に
   tk_focus 経由で復元する（モーダルトラップ判定込み）。
2. **ダイアログの初期フォーカスがダイアログ自身**:
   collect_focusable がダイアログ自身を先頭に含めるため、
   「中身の最初のフォーカス可能要素へ」という
   dialog_show_impl 自身のコメントと食い違っていた。
   あわせて Tab サイクル（focus_step）でも、フォーカス
   可能な中身があるモーダルではダイアログ自身を
   タブストップから外した（ContentDialog のモデル）。
3. **共有エディタキーの Shift+矢印が単語移動**:
   text_edit_key が Shift+矢印を TC_MOVE_WORD に写像し
   （Ctrl+矢印は単語移動にならない）両プラットフォーム
   の標準（Shift+矢印=1文字選択、Ctrl=単語、Ctrl+Shift=
   単語選択）と食い違っていた。TextField/TextView/
   SearchBar の全編集面に効く共有経路を修正。

## 発見・修正したバグ（4件、いずれも実在）

1. **メニュー/ダイアログを閉じるとフォーカスが消える**:
   表示側はフォーカスを奪うが復元が無く、候補選択や
   Esc の後にキー入力が完全に死んでいた（SearchBar
   で実証）。tk_internal.h に focus_return を追加し、
   menu_popup_at / dialog_show_impl で保存、
   tk_root_remove_overlay で tk_focus 経由の復元
   （モーダルトラップ判定込み、サブメニューの連鎖
   復元も成立）。
2. **ダイアログの初期フォーカスがダイアログ自身**:
   dialog_show_impl の自コメントと実装が不一致。
   ダイアログ自身を除く最初の子孫を選ぶよう修正し、
   focus_step でも中身のあるモーダルはダイアログ
   自身をタブストップから外した。
3. **共有エディタキーの Shift+矢印が単語移動**:
   text_edit_key の写像が両プラットフォームの標準と
   不一致（Shift=単語、Ctrl は単語にならない）。
   Shift=1文字選択、Ctrl=単語、Ctrl+Shift=単語選択
   に修正。TextField/TextView/SearchBar の全編集面と
   OSK 消費者に効く経路だが、消費者テストは無修正で
   全 PASS（既存テストはこの逸脱を固定していなかった）。

4. **FAB メニューの scrim が show/hide のたびに
   リーク**（ASan/LSan で発見）: tk_fabmenu_show が
   作る scrim は auto_free だが、tk_root_remove_overlay
   は auto_free を解放しない契約（解放は呼び出し側の
   責務で、メニュー閉鎖経路は明示的に解放している）。
   tk_fabmenu_hide だけが解放を忘れており、1回の
   表示・非表示でウィジェット1個（1,264 B）が漏れて
   いた。hide 側で remove 後に tk_widget_free する
   よう修正。修正後に LSan の直接リークは 0 件。
   なお「表示中にメニュー本体を解放する」誤用では
   scrim のフックが解放済み本体を参照する余地が
   残るが、これは hide-before-free という既存の
   ライフサイクル契約の範囲外として未修正（観察のみ
   記録する）。

  静止時の転送ゼロ契約（M13）を壊さない。Slider の
  キー操作はプログラム的アニメーションに乗せず直接
  反映する（キー1打鍵=再描画1回）。
- テスト側もキャンバス全走査は検証時のみで、製品
  コードのホットパスには何も足していない。

## キャッシュ/メモリ管理

- 本セッションでキャッシュの追加・変更は無い。
  フォーカス復元用の保存領域は tk_widget 構造体内の
  ポインタ1本（既存の menu 用領域に追加）で、動的
  確保は増えていない。
- test_tk13 を ASan/UBSan ビルドで実行し、use-after
  -free・overflow・未定義動作は検出されなかった。
  LSan の直接リークは FAB scrim の1件（上記バグ4）
  を修正して 0 件になった。残る間接リークは
  テストハーネス root_of のラッパツリー（tk_root_free
  がトップツリーを解放しない契約のため検証プロセス
  内に残る配分で、プロセス終了で回収される。既存
  スイート test_tk12 等と同作法）であり、製品コード
  のリークではない。

## 実機の現実への対応

- キー操作の網羅は抵抗膜1本指・物理キーボード併用の
  実機で「タッチが効かない場面でも全機能に到達できる」
  ための検証であり、フォーカスリングは全テーマで
  画素確認した（実機の視認性は統合フェーズの実機
  確認に委ねる）。
- 本セッションの検証は全てホスト上のユニットテスト
  である。SD イメージ/QEMU ゲスト/実機での確認は
  統合フェーズの担当で、未実施。
