## 4. 方式比較の実測（第1ラウンド）

リージョン節バイト数はデルタ符号化の模擬値（実 bake の節長と
M0 で一致することを確認済み）。

**上限内ポーズには削減を適用しない**のが正しい（後述の仕様）。

  @320 は予算 1.15 で 44 ポーズ超過、予算 1.20 で両立

## 5. 方式比較の実測（第2ラウンド: 貪欲の改良）

改良点: 和集合面積を実面積で会計（被覆カウントビットマップ
で統合の追加面積を正確に測る）、斜め隣接（縦に接し x は任意）
も候補に追加。結果は第1ラウンドとほぼ不変で、会計の保守性が
原因ではなかったことが確定した:

| 条件（ヒカリ @320、cap 100） | 矩形 mean/max | 締まり mean/max | 超過ポーズ |
|---|---|---|---|
| 貪欲・ポーズ予算 1.15 | 100.0 / 111 | 1.139 / 1.150 | 7 |
| 貪欲・予算なし（最小面積順） | 99.9 / 100 | 1.139 / **1.155** | 0 |
| （参考）@248・予算 1.15 | 100.0 / 100 | 1.125 / 1.136 | 0 |
| （参考）@248・予算なし | 100.0 / 100 | 1.125 / 1.136 | 0 |

解釈:
- @248 はポーズ単位でも 1.15 に収まる。@320 の 7 ポーズだけ
  が、≤100 にするためにポーズ締まり 1.155（従来の最大 1.147
  から +0.008）までを必要とする。引っかかるのは私が第1
  ラウンドで仮置きした「ポーズ単位 ≤1.15」という形式基準
  より厳しい制約で、形式の合格条件そのもの（ポーズ平均
  ≤1.15、最大値は併記）ではない。
- したがって **形式の合格条件の文字どおりの両立は可能**:
  全ポーズ ≤100、締まり平均 @320 1.139 / @248 1.125（どちらも
  基準内）、最大は @320 で 1.155（+0.008 の悪化を明記する）。
  基準の緩和ではない（平均基準は従来どおり、最大値は従来
  どおり報告対象）。

## 6. 採用方式（仕様）

リージョン導出は「基本タイリング＋上限超過ポーズへのみ統合」
の手続きとして定義する（上限以下のポーズのリストは従来の
帯域化ラン和集合そのもので、ミクのパックはバイト不変）:

1. 基本帯域化ラン和集合（現行定義、帯高は比例式）。
2. 矩形数が上限以下なら確定。
3. 同一 (x, w) で縦に連続する矩形を統合（和集合不変）。
4. なお超える場合、隣接ペア（縦に接する、または同一帯の
   横並び）のうち **bbox 化で新たに被覆される面積が最小** の
   ペアを繰り返し統合する（同点はリスト順）。上限以下で停止。
5. 統合で生じた重複矩形は除く（相異なる性の維持）。

上限は焼き込みパラメーター `--region-max-rects`（既定 100、
0=無制限。tol と同じくファイルには格納しない）。verify は
全ポーズの矩形数最大が上限以下であることを合格条件に追加
する。トレードオフ曲線（上限 90/100/110/無制限）は最終実装
で再実測して §7 に記録する。

  CE 側の目安（≤100）と締まりのバランスで cap 100 を既定に
