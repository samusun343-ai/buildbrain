## 4. 恒常原則への対応

- **原子的永続化 + 回復**: 全書込みは共通基盤 `bdstore` の「tmp（同一ディレクトリ）→ fsync → rename → dir fsync」。コピーは宛先を直接書かず `bd_copy_atomic` 経由（電源断で半端なファイルが最終名で残らない）。読み側は寛容: notes はメタ欠落を合成・孤児メタを除去、tasks は破損行をスキップして件数を数え、カウンタ喪失時はデータから再構築。いずれもテストで再現済み。
- **日数ベース禁止**: ゴミ箱（files）と最近削除（notes）の追い出しは容量（バイト予算）超過時に挿入連番の古い順に完全削除するのみ。tasks の期限は表示・並べ替え・スマートビュー専用で、自動削除には一切使わない。並び順は壁時計でなく永続化した単調連番（seq）が正。
- **キャッシュは予算つき**: files の画像寸法キャッシュは LRU + バイト予算（256 KiB、mtime/size で無効化、ヒット/ミス計数つき）。ゴミ箱予算は既定 32 MiB（brainreg `files/trash_budget_bytes` で変更可）。シェルのカタログ予算（1 MiB）はシェル側のものをそのまま利用。
- **コピー/オーバーヘッド削減**: タスクのクエリは store 所有ポインタを返しタスクを複製しない。ノート一覧のタイトル/プレビュー導出は先頭 1 KiB だけ読む。変換文字列は OSK/セッション所有でアプリ側コピーなし（IME 統合は OSK 既存経路をそのまま使用）。例外として明記: notes の検索/置換は textcore に検索 API がないためバッファ全体のスナップショットを取る（ノート規模では許容と判断、§5 に記録）。
- **書込み先は Brainux 領域（SD）のみ**: 3アプリとも保存先は `$HOME/.local/share/brainux/<app>`（環境変数で上書き可）配下のみ。eMMC への書込み経路は存在しない。
- **.desktop / brainreg**: 各アプリの .desktop を同梱。files は起動時にカタログ（`$BD_FILES_APP_DIRS` または標準場所）を読み、関連付けで外部アプリを起動する。表示設定（view/sort/group/show_hidden）は brainreg "files" 節、関連付けは "mime" 節に保存され、シェルと共有される。

## 5. ツールキット/シェル API の不足（SDK 検証として記録）

場当たりの内部参照はしていない。不足は全て公開 API の範囲で回避し、ここに記録する。

1. **シェルの `de_exec_argv` が `%f/%F/%u/%U` を捨てる**（desktop.h に明記された M1 制限）: ファイルを渡してアプリを開く正規手段がない。`bdmime` は Exec 展開後にパスを末尾引数として追加する方式で回避（自前アプリ群はこの規約で受ける）。シェル側で `%f` 展開を実装するのが本筋。
2. **セッタが自動 invalidate しない**（SDK 検証で実踏された落とし穴）: `tk_label_set_text` 等を呼ぶだけではダメージが記録されず、ダメージ転送が 0 バイトになる。3アプリ全てで、セッタ呼び出し後に `tk_widget_invalidate` / `tk_root_invalidate` を明示する配線にし、「イベントなしのプログラム変更 → paint_damage の rect 数 > 0 → 転送バイト > 0 → キャンバスピクセル変化」までをテストで固定した（test_files_ui / test_tasks_ui の D 群、test_notes の I 群）。
3. **画像の縮小デコード/ピクセル読み戻しの公開 API がない**: `tk_imageview_load` はウィジェット内へ丸ごとデコードするのみで、グリッド用サムネイル生成に使えない。bd-files のグリッドは種別アイコン + 寸法バッジで代替し、寸法は PNG/JPEG/GIF ヘッダの自前スニッフ（数十バイト読み）+ 予算つき LRU で賄った。サムネイル API の追加が望ましい。
4. **ファイル選択ダイアログがない**: notes の添付はパス入力ダイアログで代替。bd-files 自体が選択 UI を提供する形が本筋。
5. **ListView の行が文字列のみ**（アイコン・チェック・複数列なし）: tasks の完了状態・優先度、files の種別・グループ見出しは全てテキスト表現で代替した。列ヘッダつき詳細ビューと行内チェックはウィジェット側の拡張待ち。
6. **日付/時刻ピッカーがない**: tasks の期限はテキスト入力 + モデル側検証で代替。
7. **textcore に検索 API がない**: notes の検索/置換はスナップショット上の strstr で実装（§4 の例外として記録）。
