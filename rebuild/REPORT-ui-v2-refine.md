# UI v2 精錬フェーズ報告

位置づけ: UI-STYLE-v2 パイロット4画面へのユーザー評価
「微妙に使いづらそう。デザイン/レイアウトがまだ荒い」を受けた
精錬フェーズ。方向（大きな角丸・ピル・トーナル・浮動 Shelf）は
維持し、全面展開の前にレイアウトと使い勝手の粗さを潰した。
変更範囲は v2 テーマ＋シェル＋設定アプリ＋基盤部品の欠陥修正。
repo へは push していない。

## 0. 実物再確認（今回の修正の根拠）

記憶で直さず、一次・準一次ソースを再確認してから直した。

- **Samsung Developer 公式「Basic layout」**
  (https://developer.samsung.com/one-ui/layout/basic.html):
  画面上部は viewing area（タイトルだけ、広い余白、タッチ要素を
  置かない）、残りは interaction area。コンテンツは focus block
  （カード/グループ化リスト）でカテゴリ別にまとめる。
- **ChromeOS 117 Quick Settings**（9to5google の実機解説
  https://9to5google.com/2023/09/27/chromeos-117-material-you/）:
  角丸矩形タイルのグリッド、その下にスライダー群（アイコンは
  スライダーの横）、最下段に設定ショートカット等。スライダーは
  太く、アイコンは単色シンボル。
- **ChromeOS Launcher**（PCMag の ChromeOS 解説）: 検索＋最近
  使ったものが上部、その下に全アプリのライブラリが続き、
  スクロールで全体を辿る。
- **Material 3**（UI-STYLE-v2.md §1 で確定済みの値）: チップは
  full 角丸、検索バーは full 角丸の充填、リスト行 56/72、
  スライダーは太トラック＋明確なハンドル。

## 1. 直した粗さ（項目別）

### 1.1 設定：見出しと検索ピルの同居、余白リズム

| 粗さ（パイロット） | 修正 | 実物の何に合わせたか |
|---|---|---|
| ページ見出し「画面」が検索ピルの横（別ペインの同じ帯）に同居して窮屈 | 検索をサイドバーから出し、大見出しの下に**全幅ピル**として配置。ページ見出しは右ペイン先頭に単独で置く | One UI 基本レイアウト（タイトル=viewing area、操作要素はその下の interaction area）＋ ChromeOS 設定の「タイトル下に全幅検索」 |
| 見出しとカードの間隔が詰まる（box spacing 4） | v2 の全間隔を **8** に統一、外周パディング 12→**16** | 8px グリッド（UI-STYLE-v2 §3-6 の余白スケール） |
| 左カードと右カードの上端が検索分ずれて不揃い | 両ペインが同じ y から始まる構成に変更。実測: 左リスト上端 y=122、右ペイン見出し帯の開始 y=121（一致）。右カードは見出し帯（28+8）の下 y=159 | ChromeOS 設定の2ペイン形（左ナビ上端＝右ペイン見出し、カードは見出しの下） |

右カードの「間延び」は、画面ページの行が実際に2行しかない
（輝度＋バックエンド）ことが主因で、レイアウト欠陥ではないと
切り分けた。撮影は行選択時のエディタ（スライダー）表示状態と、
5行あるキーボードページ（v2_15）を追加して判断可能にした。

### 1.2 ランチャー：チップ、空き、フッター、検索枠

| 粗さ | 修正 | 根拠 |
|---|---|---|
| チップの折り返しが不揃い（間隔 4px、面なしで文字だけが浮く） | 高さ **40** のピルに統一し、間隔を横 **8** / 縦 **8**（ピッチ 48）に。未選択チップにも surface_alt の面を持たせ「チップの群」として読めるようにした（選択時は selection 面、従来どおり） | M3 フィルタチップ（full 角丸＋トーン面、8dp 間隔のチップグループ） |
| グリッド領域の空きすぎ | (a) 撮影データを実データ化（ピン6件＋最近3件、§2）。(b) ホーム節の下に余った領域へ**全アプリグリッド**を流し込むようレイアウト変更（ピンが少ない構成でも空白の void が残らない） | ChromeOS Launcher（おすすめ/最近が上、全ライブラリが下に続く） |
| 左下に浮く "brain" ラベル | 正体はフッターのユーザー名ラベル（アバターなし・帯の上端に文字だけ）。**アバター円盤（デフォルトの人物シルエット）＋帯中央に名前**のユーザーチップ形に変更 | ChromeOS / Windows のユーザーチップ（アバター＋名前） |
| 検索ピルのフォーカス枠が太く重い | v2 のテキストフィールドに限り、フォーカスリングを「1px・フィールド自身の縁」に変更（従来は 2px・1px 外側）。他の部品のリングは不変 | M3 充填フィールドのフォーカス表示は控えめなインジケータ |
| （撮影で新規発見）ピン2行目のラベル「NetSurf Web Browser」がセルをはみ出して隣と衝突 | 基盤側でアイコンセルのラベルを**セル幅に省略描画**（…付き、UTF-8 境界で切断）。デスクトップ側はセルが文字幅で測られるため無影響 | 実ランチャーのアイコンラベル省略（Android/ChromeOS） |
| （同）ピン行数が収容可能行数を超えるとチップ行へはみ出す | レイアウトで収容可能行数にキャップし、超過セルを隠す（シェルフと全アプリグリッドには残る） | —（幾何の安全策） |

### 1.3 クイック設定：アイコン、ハンドル、余白

| 粗さ | 修正 | 根拠 |
|---|---|---|
| 輝度アイコンが多色の奇妙なグリフ（青い円盤＋橙の太陽の Papirus ファイルが 24px でパイ状に読める） | アイコン解決の誤りと特定。スライダー行のアイコンをトレイと同じ**シンボリックグリフ**（単色の太陽 / スピーカー）に置換。実測: 輝度アイコン領域の非背景色は ink 1色のみ | ChromeOS QS のスライダー横アイコンは単色シンボル |
| スライダーのハンドルが小さな点 | 描画コードは白丸28＋accent中心を描いていたが、白いパネル上では輪郭がなく中心点だけが見えていた。**1px の輪郭リング**を追加し 28px ハンドル全体が読めるようにした。実測: ハンドル中心行に輪郭色ピクセルを確認 | UI-STYLE-v2 §4 の定義（白ハンドル＋accent中心）どおりの見え方に復帰 |
| パネル幅と内側余白のバランス | 値ラベルの右端がパネル内端を 4px はみ出していたのを修正。左端（タイル/アイコン列 x=12）、スライダー 44..296、値 304..348 で右端がタイル右端 348 と一致 | 8px リズムへの監査結果 |

### 1.4 デスクトップ / シェルフ / アシスト

| 粗さ | 修正 | 根拠 |
|---|---|---|
| ピン留め2件とも黄色ドキュメントタイル | 正体は別アプリのアイコン未解決ではなく、ピン2件（ライター/メモ）が**両方とも notes アイコンに解決される**データ側の問題＋撮影データの少なさ。実データ化（§2）で6件すべて別アイコンに。製品側の解決経路は元々正常 | Papirus 統一セット（既存の ic_resolve 経路） |
| Shelf 内アイコンも同様 | 同上（同じピンを表示するため自動的に解消） | — |
| アシスト FAB が右端中段に浮く | v2（浮動 Shelf）では FAB を **Shelf の角グリッドにドック**: 右マージン 8（Shelf と同一）、下端はメイン領域下端から 8。グリフ色も固定青からテーマ accent に追随（クラシックは同値で不変） | ChromeOS のアクセシビリティボタンは Shelf/ステータス領域に統合される慣行 |

### 1.5 全体監査（余白・ターゲット実測）

- 余白: 設定（8 統一・外周 16）、ランチャー（検索 12/16、間隔 8、
  チップピッチ 48、フッター帯 48）、QS（内周 12、行ピッチ 48、
  右端 348 で整列）を 8 の倍数に統一した。QS の内周 12 と
  ランチャー検索の上 12 は浮動面の慣行値として残置（面の
  パディングは 12/16 が M3 のシート/カード標準域）。
- タッチターゲット実測（rect = 当たり判定）: Shelf ボタン 56
  （パネル高）、QS タイル 72、QS スライダー 48、設定行 56/72、
  アシスト行 56、FAB 56、ランチャーのアイコンセル 76、
  フッターのロック 48、トレイ 48。
  **唯一の例外: カテゴリチップ 40**。M3 チップの見た目高さは
  32 で、本機は 40 まで上げてあるが一次/通常の 48 には届かない。
  8px の間隔があるため誤タップは隣ではなく隙間に落ちる。
  48 にするとチップが3行になり中段が潰れるため、精錬では
  40 を採用し、例外として明記する。

## 6. 残件・正直な限界

- チップのタッチターゲット 40 は 48 未満（§1.5 のとおり例外
  として残置。48 化はチップ3行化と引き換え）。
- 800×480 ではピン2行＋最近表示が同時には収まらず、ピンを
  優先し最近は空きがある構成でのみ出る（ChromeOS の
  peeking ランチャーと同じ「1節だけ見せる」トレードオフ）。
- 設定の表示ページは行が2つしかなく、カード下部は空く。
  レイアウトではなくモデル側の収録行数の話で、本フェーズの
  範囲外（行の追加はアプリ機能の変更になる）。
- 設定キーボードページは行リストがスクロール前提（5行中
  3行＋スクロールバー）。隠しエディタ帯を含むボックス
  レイアウトの従来挙動で、v2 の回帰ではない。
- アシストパネルのステータス行はパネル角丸の近くで余白が
  やや詰まって見える（表示は欠けていない）。次フェーズの
  全面展開時にパネル内周と合わせて詰める候補。
- 実機/QEMU ゲストでの実操作検証は未実施（統合フェーズの
  合格条件に従う）。本報告はホスト撮影＋ピクセル実測＋
  全テスト回帰ゼロまでの完了報告。
