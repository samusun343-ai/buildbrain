> 参照する場合は、前提として扱わず、一次資料と照合して独立に検証すること。


ユーザーの決定（2026-11-20）を受けた OSK のレイアウト方針変更:

- 「日本語での仮想キーボードは使いずらいので **QWERTY+α** での日本語、
英語、その他! などの文字入力で」
- 「仮想キーボードは物理キーでは入力できないものも入力できるようにする」
（OSK は物理キーボードのスーパーセットであること）
- 「仮想キーボードと統合はするけど混ぜたらいけない」
（入力経路の統合は維持、OSK を物理配列の模倣に縛らない）

repo へは push していない。変更は `src/tk_osk.c`、`include/osk.h`、
`osk/tests/test_osk.c` の3ファイルのみ（ツールキット本体
tk_widgets.c / textcore.c / tk_core.c には触れていない）。

## 1. 方針変更の内容

### 1.1 QWERTY を既定・主レイアウトに

- `tk_osk_new()` の初期モードを `OSK_MODE_FLICK` から
`OSK_MODE_QWERTY` に変更。新規ウィジェットは QWERTY で開く
（テスト E で検証）。
- 日本語は QWERTY ローマ字入力 → libbrainime 変換が主経路
（従来からある経路をそのまま主役にした）。
- **英語（英数）サブモードを新設**: 下部バーの「英数」セル
（`OSK_FN_LANG`）で切替。英数中は英字キーが reading を経由せず
`TK_EV_TEXT_INPUT` でターゲットへ直接コミットされる
（`tk_osk_set_direct()` / `tk_osk_direct()`）。候補バーの
表示名も「英数入力」になる。物理キー経路（`TK_EV_TEXT_INPUT`
イベント）も英数中は直接コミットになる（物理側の Shift/Caps は
tk_kbd が処理済みで、OSK のシフト状態とは干渉しない）。
- **QWERTY にシフトキーを新設**（3行目左端、`OSK_FN_SHIFT`）:
タップで オフ → ワンショット → ロック → オフ。ワンショットは
次の英字1文字で消費され、ロック中は英字ラベルが大文字のまま
保持される。シフト有効中はキー自体がハイライト表示される。
3行目は [⇧][z x c v b n m][削除] の物理キー風配置になった。
- モード切替の循環順を変更: **QWERTY → 記号 → 50音 → フリック
→ QWERTY**（`osk_next_mode()` で明示。下部バーのモードセルの
ラベルは移動先の名前を表示）。

### 1.2 フリック/50音の降格

- 削除はしていない。どちらも従来どおり動作する（テスト C/D/G/V
が引き続き全 PASS）。
- ただし導線の主役からは外した: 既定は QWERTY、循環でも
フリックは最後尾。50音・フリックを使うテストは冒頭で明示的に
モードを設定するよう更新し、「既定でフリックが開く」前提は
コード・テストの両方から消した。

### 1.3 統合と分離の線引き（「混ぜない」の実装上の意味）

- 統合の維持: OSK の全レイアウトと物理キーボードは、従来どおり
同一の reading → IME セッション → composition / TEXT_INPUT
という経路に合流する（テスト U の統一経路検証は無変更で PASS）。
- 混ぜない: OSK のレイアウト設計は物理配列に従属しない。
QWERTY はローマ字入力のための配列であり、物理 JIS 配列の
句読点位置（@キー、¥キー等）は模倣していない。記号は物理キー
の有無と無関係にカテゴリページで網羅する（§2）。英数 direct
のように「物理キーには無い入力様式」も OSK 側に持てる。

## 2. 記号ページ（+α）の拡充とカバー表

従来2ページ（数字・約物ページ＋英大文字ページ、入力文字78字）
を **8カテゴリページ・入力文字289字** に再編した。英大文字
ページは廃止した（英字は QWERTY の担当になり、小文字も打てる
ようになったため、カバーはむしろ増えている）。ページ切替
セルのラベルは移動先ページ名。公開 API
`tk_osk_symbol_page()` / `tk_osk_set_symbol_page()` /
`osk_symbol_page_count()` / `osk_symbol_page_name()` を追加。

凡例（「物理キー」列）:
- **○** = Brain 物理キーボード（JIS 配列、`tk_kbd` のキー定義表）
の直接打鍵で入力可能
- **△** = 物理キーからの日本語入力で到達可能（ローマ字入力の
約物変換 、→「、」等、および辞書の単語/記号変換の候補。
辞書エントリ依存のものを含む）
- **×** = 物理キーボードでは入力不可。**OSK でのみ入力可能**

### ページ0「基本」（39字）— 数字・和文約物・常用演算子

| 分類 | 文字 |
|---|---|
| ○ (10) | 1 2 3 4 5 6 7 8 9 0 |
| △ (16) | 、 。 ・ ー … ‥ ！ ？ ： ； （ ） 「 」 『 』 |
| × (13) | ＋ － ＝ ／ ＼ ％ ＃ ＆ ＊ ＠ ［ ］ ｛ |

### ページ1「半角」（39字）— 半角 ASCII 記号の完全集合＋一般記号

| 分類 | 文字 |
|---|---|
| ○ (32) |! " # $ % & ' () * +, -. /:; < = >? @ [ \] ^ _ ` { \|} ~ |
| × (7) | § ¶ © ® ™ • — |

半角 ASCII 記号32字は欠けなし（JIS 物理キーでは Shift+7 が '
のように位置が US と異なるが、全て直接打鍵の範囲内）。

### ページ2「全角」（37字）— 全角形・括弧・和文記号

| 分類 | 文字 |
|---|---|
| △ (17) | 〈 〉 《 》 〔 〕 ※ ゛ ゜ 々 〃 ゝ ゞ ヽ ヾ |
| × (20) | « » ‹ › ＂ ＇ ｀ ＾ ～ ＿ ｜ ￥ ＄ ， ． ＜ ＞ ｟ ｠ 全角空白 |

注: ￥（U+FFE5）は物理 ¥ キーが出す ¥（U+00A5）とは別文字で ×。
全角空白（U+3000）はセル上「全角空白」と表示して入力する。

### ページ3「単位」（39字）— 矢印・通貨・単位・数学・図形

| 分類 | 文字 |
|---|---|
| ○ (2) | ¥ $ |
| △ (4) | ← → ↑ ↓ |
| × (33) | ↖ ↗ ↘ ↙ ⇐ ⇒ € £ ¢ ° ℃ ℉ ′ ″ − × ÷ ≠ ≤ ≥ ± ∞ √ ∑ ● ○ ◎ ★ ☆ ♪ ▲ △ ▼ |

### ページ4「アクセント」（39字）— アクセント付きラテン小文字＋大文字頭

à á â ä ã å æ ç è é ê ë ì í î ï ñ ò ó ô ö õ ø ù ú û ü ý ÿ ß
À Á Â Ä Ã Å Æ Ç È — **全て ×**（物理キーにデッドキーなし）

### ページ5「大文字」（39字）— アクセント大文字残り＋ラテン拡張

É Ê Ë Ì Í Î Ï Ñ Ò Ó Ô Ö Õ Ø Ù Ú Û Ü Ý Ÿ ā ē ī ō ū Ā Ē Ī Ō Ū
œ Œ ł Ł đ Đ ħ Ħ Š — **全て ×**（ā 行はローマ字長音表記用）

### ページ6「ギリシャ」（39字）— ギリシャ小文字＋大文字頭

α β γ δ ε ζ η θ ι κ λ μ ν ξ π ρ σ τ υ φ χ ψ ω ς
Α Β Γ Δ Ε Ζ Η Θ Ι Κ Λ Μ Ν Ξ Π — **全て ×**

### ページ7「ギリシャ大」（18字）— ギリシャ大文字残り＋変形文字

Ρ Σ Τ Υ Φ Χ Ψ Ω ϑ ϕ ϖ ϰ ϱ ϵ ϒ ϓ ϔ µ — **全て ×**
（µ は μ とは別文字のマイクロ記号 U+00B5）

### スーパーセットであることの証明

- 物理キーの直接打鍵で出せる印字可能文字は、英字（QWERTY、
シフトで大文字）、数字（ページ0）、半角記号32字（ページ1）、
¥（ページ3）、$（ページ1/3）の全てが OSK 側にも存在する。
- それに加えて **× の208字は OSK でしか入力できず**、△の37字も
物理側では変換候補頼みで確実ではない。OSK の入力可能文字は
物理キーボードの真のスーパーセットである。
- 合計: ○44 / △37 / ×208 = **289字**（実コードから公開
レイアウト API で列挙して集計。テスト X が全字の入力→
コミットまでを通しで検証）。

## 3. キーサイズ実測

公開レイアウト API で実測（ダンプツールで取得）:

| 対象 | 幅800px（設計幅） | 幅480px（最小幅） |
|---|---|---|
| QWERTY 1行目英字 | **80×56** | 48×56 |
| QWERTY 2・3行目英字 | **88×56** | 53×56 |
| シフト / 削除 | **88×56 / 96×56** | 53×56 / 56×56 |
| 記号セル | **80×56** | 48×56 |
| フリックキー | 242×60 | 136×60 |
| 50音セル | 160×56 | 96×56 |

- 設計幅800px（Brain の横向き画面）では全入力キーが縦横とも
≥56px を満たす。
- **正直な限界**: 幅480pxでは高さ56pxは全キーで維持されるが、
10列行のキー幅は48px（記号・QWERTY 1行目）、9列行は53pxに
なる。10列 × 56px = 560px > 480px であり、列を減らさない
限り物理的に両立しない。480px幅は最小幅（テスト・縦持ち）
として扱い、要求は設計幅で満たす、という線引きを明記する。

### テスト実行時の注意（再掲）

`test_osk` を直接実行する際、辞書の sidecar は絶対パスで
渡すこと。相対パスだと engine が sidecar を読めず、変換結果が
変わって D/K/U/W/P が FAIL する（`make check` は絶対パスで
渡すため問題ない）。本作業中にもこの踏み間違いで一度
「全滅」に見えたが、実行条件の問題であり回帰ではなかった。

## 6. 未実装・残り（正直な一覧）

- **記号の直接コミット**: 記号セルは従来どおり reading
（composition）に合流する。英数 direct の最中でも記号ページへ
行くとモード自体が切り替わり、記号は変換経由の確定が要る。
「英数中は記号も直接コミット」は未実装。
- **QWERTY の数字行なし**: 数字は記号ページ「基本」か物理キー
で入力する設計にした。タブレット型キーボードのような
4行目（数字行）の追加は要否判断待ち。
- **480px 幅でのキー幅**: §3 のとおり、高さは満たすが幅は
48〜53px。設計幅800px前提で要求を満たす扱い。
- **ギリシャ大ページの空き行**: 8ページ中このページだけ
2行分しか使っていない（カテゴリ分割の結果）。実害はない。
- **グリーターの初期サブモード**: braingreeter2 は
`tk_osk_new()` の既定（QWERTY・日本語）で開くようになった。
パスワード入力向けに英数 direct を初期状態にする配線は
シェル/グリーター側のフォローアップ。
- **シェルスイートのビルド不可（担当外・作業時点の状態）**:
`shell/` の `make check` が `shell/include/wifi.h` の
typedef と同名関数の衝突（51行/71行）で失敗する。DE M3
ラインが同時刻に編集中のファイルであり、本変更
（tk_osk.c / osk.h / test_osk.c）とは無関係
（shellui.c は osk.h を include していない）。そちらの
ラインの修正待ちで、OSK 側の回帰ではない。
- **libbrainime の UBSan 指摘（担当外）**: ASan/UBSan 実行で
`libbrainime/src/engine.c:1892` に「nonnull 引数への NULL
渡し」が1件出た（test_osk の結果自体は全 PASS）。IME
ラインの範囲として報告に留める。
- **ゲスト/実機検証**: 本 M3 はホスト単体テストまで。SD
イメージ＋QEMU ゲストでの実操作検証は統合フェーズの
合格条件に従う。
- 変換品質は libbrainime の水準のまま（本作業はレイアウトと
入力様式の変更）。
