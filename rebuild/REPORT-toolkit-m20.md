**コピー / オーバーヘッド削減（本弾の実装分）**:
- #21 の scale 転写は入場・退場のアニメーション
  中だけ走り、静止時（paint_scale = 1000）は
  従来経路とバイト同一で追加コストゼロ。
  転写フットプリントは既存ダメージ矩形の内側に
  収まり、追加転送は発生しない。
**キャッシュ / メモリ管理**: スクラッチ面は
ルート所有の2面を使い回し、最大のスケール対象
矩形でサイズを決め再利用する（上限はルート面
サイズ）。フレームごとの確保はしない。
**実機の現実への対応**: 本弾の変更は描画基盤と
寸法解決のみで、永続状態・オフライン前提には
触れていない。オフスクリーン捕獲は RAM 予算に
対しルート面サイズを上限とする設計で、128MB
予算との両立をこの上限で担保する（実測の裏付け
範囲は「未検証の明記」参照）。

## 未検証の明記

- 消費者バイナリは静的リンクのため、実行確認は
  旧ライブラリを含むビルド済みバイナリの動作
  確認であり、M20 のライブラリ変更に対する
  消費者の再ビルド回帰ではない。再ビルドを伴う
  消費者回帰は統合ラインの範囲（本弾の制約で
  ツリーへ書き込まないため実施していない）。
  ライブラリ変更面（メニュー scale 経路・リング
  寸法解決）の回帰は tk16 / tk17 と sdk-check
  （公開ヘッダ + 共有ライブラリで実行）が担う。
- #21 のフェード中は、捕獲矩形に含まれる背後の
  背景も一緒にスケールされる過渡特性がある
  （入場 ≤167ms のみ、静止時はバイト同一を
  テストで固定済み）。参照実装との画素単位の
  一致ではなく、形（フェード + scale の併用と
  時間・原点）の一致として ● とした。
- Android #12 のトークン値 Size = 40dp は、
  一次ソース（ProgressIndicator.kt の参照関係）
  と、それを引く第三者実装のコミットによる
  裏取りであり、トークン定義ファイル自体の
  直接取得ではない。
- (a) 11件と Slider ピル型はユーザーの判断が
  無い限り分類・形状を動かさない。判断材料の
  撮影はホスト描画であり、ゲスト/実機での
  撮影ではない。
- ARM 実機・QEMU ゲストでの動作確認は本弾の
  範囲外（統合フェーズの担当）。
