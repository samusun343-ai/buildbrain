## P1 トークンと基盤（実施済み）

- **トークン**: `tk_theme` に desktop_bg / border_line /
  radius_overlay / row_h2 / フォント5段（display 28 / title 20 /
  heading 16 / body 16 / caption 13）を追加。実値: control_h 48、
  row_h 48、row_h2 64、角丸はコントロール 4・浮動面 8。
  text_dim #6E6E76→**#5A5A61**、border #C6C6CC→**#8A8A92**、
  border_line #D8D8DE を新設。
- **コントラスト実測**（test_tk3 で sRGB 相対輝度から自動検証）:
  text_dim 対 surface / surface_alt で ≥4.5:1、border 対 surface で
  ≥3.0:1（実値 約3.4:1）、text / accent 上の on_accent も検証。
- **タイポグラフィ**: テキスト描画を px パラメータ化し、スタイル
  API（`tk_text_style`、`tk_widget_set_text_style`）を新設。
  太字フェイスが同梱フォントに無いため title/heading は同一
  グリフの 1px オフセット重ね描きによる合成ボールド（送り幅
  不変＝レイアウトは一切ずれない）。
- **ウィジェット寸法**: スライダーつまみ直径28の正円（ヒット高
  48）、スイッチ 52×32・ノブ24（位置＋色の二重表現）、タブ高48
  （選択中は太字＋accent 下線3px）、ListView は選択の二重表現
  （selection 面＋左3px accent バー）、2行モード（subitems、
  行高64）、行アイコン API、スクロールバーサムはスクロール
  可能な間は常時表示。
- **OverflowBar**（新規部品）: 収まらない子を非表示＋矩形0に
  して「»」ゾーンへ落とし、ポップアップメニューから子自身の
  クリックを発火。幅が戻れば自動復帰。test_tk3 で落下順と
  メニュー経由発火を検証。
- **ImageView フォールバック**: 画像なし時は全面プレートを
  廃止し、中央に汎用ピクトグラム（枠＋太陽＋山並み）。
- **OSK**: 候補バー48＋チップ化（全丸、選択中 accent＋白文字）、
  キーはギャップ 4（800幅）/2（480幅）＋角丸6、記号ページは
  候補バー位置にカテゴリチップ列（8カテゴリ）、高さは段階圧縮
  （56→48→44）で必ず収まる契約を実装。標準高 328（フリック/
  記号）、480×272 では画面高60%以内。
- **グリフキャッシュ実測**（§2.5）: 実用混在テキスト18行を
  1スタイル vs 5スタイルで描画するベンチで、ピーク RSS
  11,400 KiB → 11,564 KiB（**+164 KiB**、追加グリフ1件あたり
  約0.57 KiB）。既存キャッシュ予算内に収まる。

## P3 アプリ別レイアウト（実施済み）

- **files**: パンくずをナビ行へ統合しパス二重表示を廃止
  （パス入力は切替式の行、初期は非表示）。操作群は
  OverflowBar 化（開く/新規フォルダ/貼付が常時表示、残りは
  »）。選択時アクションバー（高さ56相当）を新設。サイドバー
  は 176 幅（min-size API を新設）＋場所7件（ホーム/
  ダウンロード/ドキュメント/画像/音楽/SDカード/ゴミ箱）＋
  空き容量 caption と細バー（statvfs、容量ベース）。一覧は
  2行化（名前＋サイズ・種類）＋種別アイコン6種（起動時に
  描画、借用ポインタでコピーなし）。ステータスは「9 項目」
  形式。
- **notes**: 3ペイン化（フォルダ160/一覧224/編集 残り）。
  検索はヘッダーのトグルで出す検索バーに分離し、置換は
  その中の展開時のみ。書式ツールバーは OverflowBar で1段＋»。
- **settings**: サイドバー 176（下限）＋検索欄、行は2行形式
  （ラベル＋値 caption）。「次の値/実行」ボタンを**廃止**し、
  cycle/action 行は行自身のアクティベーション（ダブル
  タップ/Enter）で発火する対話モデルへ移行（公開 API

  欄のページ限定表示は維持。開発用文字列の env ゲートは、
  対象となる行がモデル内に存在しないことを確認した（該当
  なし）。
- **calc**: 結果は display 28・右寄せ（ラベル整列 API を
  新設）、タブ48、キー面の色分け（数字=surface、演算子列=
  surface_alt、==accent 全幅、C/AC=danger 文字色、() は
  同行）。履歴は「直近1件 caption＋履歴ボタン→シート
  （ダイアログ、幅224）」に分離し、常時表示リストを廃止。
- **player**: Now Playing バーを下部固定のカラム構成に再編
  （アート48｜タイトル/アーティスト/アルバム｜進行バー
  （スライダー＋時刻 caption）｜トランスポート（再生は
  56・角丸28・accent）｜音量トグル＋展開スライダー）。
  進行バーをタイトル下の行から独立カラムへ移したのは、
  スライダーの実測高（ヒット高48）がバー全体を 100px 超に
  引き伸ばす不具合を撮影で確認したため。キューは専用
  ビュー（トグル表示）に分離し、↑↓ 並べ替えボタンを
  `pl_order_queue_move` と接続。再生中行のマーク（左
  accent バー）は既存の marked 機構が担う。
  併せて実バグを修正: アートのプレースホルダ色にアルファが
  無く、合成で透明になりアート欄が空白になっていた
  （0xFF を付与）。
- **clock / tasks / recorder / pkg / admin**: 仕様 §2.4 に
  個別方針の記載がないため、トークン継承（コントロール48、

## 撮影で発見し修正した不具合（本フェーズ）

1. OSK 記号カテゴリチップがセル振り分けのミスで構築されず
   消えていた。
2. 閉じたランチャーの検索欄（隠れたフォーカス中ウィジェット）
   のフォーカス枠がデスクトップ上に残っていた。
3. ランチャー中段の子要素がカテゴリチップ行に被さり、最近
   リストの高さが負数になっていた。
4. クイック設定の Wi-Fi タイルでラベルが二重描画されていた。
5. FAB とクイック設定フッター（ロック）の重なり。
6. グリーターのユーザー切替リストが画面下端を溢れ、電源
   ボタンと重なっていた（カード位置とリスト高の適応化で解消）。
7. ランチャーの「最近使った」が空でも見出しと空の枠が残った。
8. player の NP バー引き伸ばし（上記）とアート透明化（上記）。
9. files の汎用ファイルアイコンが空の四角（チェックボックス）
   に見えたため、折り目＋本文線のあるページ glyph に変更。

## 未実施・残課題（正直なリスト）

- **ランチャーのピン留め切替 UI** は新レイアウトに置き場が
  なく削除した（モデル/store API は不変。長押しメニュー等が
  必要なら別途設計が要る）。
- **電源ボタン群**: ランチャーフッターの再起動/電源オフは
  session に電源 API がないため未配線（ロックのみ）。
  グリーターの電源ボタンは終了コード（4=電源オフ、
  5=再起動）でセッションスクリプトへ渡す継ぎ目までで、
  スクリプト側の消費は未統合。
- **WM タイトルバーのアプリアイコン** は未実装（ウィンドウ
  プロトコルにアイコン欄がない）。
- **WM の閉じるボタンの danger 面** は押下時のみの仕様だが、
  WM chrome は押下状態を保持せず pointer-down で即実行する
  ため未対応（グリフは通常色）。
- **OverflowBar の落下ボタン** はフォーカスチェーンに残る
  （キーボードフォーカスが不可視ボタンへ移る場合がある）。
- **グリーターの切替リスト行は 48**（仕様は56。ツールキット
  の ListView 行高が 48/64 のため48を選択）。時計は display
  28（仕様の「48級に拡大してよい」は任意事項）。
- **settings の行** は左右1行完結ではなく2行（ラベル/値）
  形式。グループ見出しはモデルにグループ概念がないため
  未対応。サイドバー幅は flex で 176 を超えて伸びる（176 は
  下限として実装）。
- **player の NP バー高は約90**（仕様72。アルバム行と
  スライダーのヒット高48のため）。再生ボタンの ⏸ グリフが
  測定幅より広く、ピルの右端にわずかに触れる。
- **calc の式表示** は表示専用 caption ではなく編集可能な
  フィールドのまま（物理キーボードからの直接入力を残す
  ための意図的な選択）。
- **files のサイドバー場所リスト** は7行×48が縦に収まらず
  スクロールする（スクロールバーは常時表示）。
- **時計シートのカレンダー** は未実装（仕様側の未決定事項。
  通知のみで開始可とされている）。
- **壁紙の既定**（画像か色か）と**ダークテーマの要否**は
  仕様側の未決定事項のまま。現行は desktop_bg トークンの色
  （ライトテーマ正、トークン構造のみ維持）。

## 恒常原則への対応

- **コピー/オーバーヘッド削減**: 影は出現時のみ描画し常時
  コストゼロ（ダメージは +4px 分のみ）。ListView の行アイコン
  は借用ポインタ（コピーなし）。files の行アイコン6種は起動時
  に一度だけ描画。シェルのトレイグリフは状態変化時のみ再生成。
- **キャッシュ/メモリ管理**: アイコンはシェルの単一キャッシュ
  （予算 2MiB）を全画面で共有し、新規の常駐メモリは作って
  いない。5段タイポグラフィのグリフキャッシュ増分は実測
  +164 KiB（上記）。files の空き容量表示は statvfs の容量
  ベースで、日数ベースの基準は使っていない。
- **実機の現実**: 本フェーズは表示層のみで、永続状態の形式は
  変更していない（設定の保存経路・原子性は従来どおり）。
  オフライン前提・時刻不信に触れる新規の時間依存は追加して
  いない（グリーター時計は表示のみ）。
