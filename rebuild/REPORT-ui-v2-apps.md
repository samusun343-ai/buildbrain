## 2. 設定アプリ: 操作モデルの作り直し（最優先）

### 2.1 何が問題だったか
行を選ぶと画面下部に「調整:」スライダーが**カードの外**に現れる分離型。値を見る・変えるために視線と指が行と画面下部を往復する。ユーザー評価:「そもそも使いづらい」。

### 2.2 Web 調査とレイアウト判断
- ChromeOS 設定: 左ナビ幅 250〜266px（Chromium settings_ui.html の `--settings-menu-width`）、Material You 再設計（ChromeOS 124）でも「左ナビ＋各セクションが角丸コンテナ内の独立ページ」。
- One UI 公式デザインガイド: Viewing area / Interaction area の分離とフォーカスブロック（カード）。
- 判断: **2ペイン維持**。800×480 横画面では実物2者とも2ペインであり、単一カラムは行が間延びする。変えるべきはペイン構成ではなく行内の操作モデル。

### 2.3 新しい操作モデル（実装済み）
行は「ヘッダ（名前＋現在値キャプション）＋行内エディタ」の単一グループカード構成（ListView 廃止、scrollview 内カード）:
- **トグル**: ヘッダ右のスイッチをタップで即切替（モデルが拒否したら復帰）。
- **スライダー**: ヘッダ直下に本体。ドラッグ中は再構築せずモデル書込み＋値ラベルのみ更新。
- **選択（cycle）**: ヘッダ直下に全選択肢のチップ行。タップで即選択。
- **実行（action）**: ヘッダ右にピルボタン。セキュリティ付き AP はタップで **PSK フォームがその行の直下に展開**。
- 選択ハイライトは行自身の backdrop。全ページで「値がその場で見え、その場で変わる」形に統一。

### 2.4 モデル側の変更
- `SR_TOGGLE` 行種別を追加。Wi-Fi ページ先頭に **wifi_on トグル**を新設（正本は brainreg `shell/wifi`、シェルの QS タイルと同一経路。bd_backend/bd_wifi に電源 API が無いため捏造トグルは作らなかった）。
- キーボード preset 行・電源 sleep 行に選択肢一覧を持たせチップ化。
- **画面ページの「バックエンド」情報行（値 "mock"）を削除** — 開発者向けアーティファクトが製品画面に残らないように。
- テスト: test_settings 30 / test_settings_ui 13 全 PASS（チェック数不変）。
