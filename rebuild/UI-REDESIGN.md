### 本機の前提（全ての判断の土台）

- 画面: **800×480 が主、480×272 が副**。タッチは**抵抗膜・1本指のみ**（マルチタッチ、ホバー、ピンチは存在しない）。物理キーボード併用（48キー、Brain 専用キーあり）。
- 描画: fbdev、RGB565 変換＋ダメージ駆動転送。**GPU はなく、ブラーや広域の半透明合成は転送量と CPU の両面で払えない**（§2.5 で代替表現を定義）。
- RAM 128MB。シェル常駐予算は DESIGN-shell-v2 §2.2 の約10MiB を維持する。
- ユーザーの既定方針（2026-11-20 評価文書）: 単一の独自デザイン。Win11 風スタートをベースに macOS のアプリグリッド/Dock の考え方と GNOME/KDE 的な一貫性を取り入れる。アイコンは Papirus（単一セット）を使用中。

# 第1部: 画面ごとの問題診断

## 1.0 横断診断（13画面に共通する構造的問題）

個別画面の前に、全画面を貫く問題を先に挙げる。多くは「部品はあるが、デスクトップ製品の文法で組まれていない」ことに起因する。

- **X1. アイコンがどこにも描かれていない。** 13画面全てがテキストのみで構成される。ランチャーのアプリ一覧、デスクトップ、ファイルマネージャーの一覧、パネル、設定のサイドバー——全て文字だけである。主要 DE は全てアイコン中心（S3/S6/S8/S10）であり、「アイコン＋ラベル」がアプリや場所の識別の基本単位。現行は Papirus を取得済みにもかかわらず、シェル側のアイコンテーマ解決と描画が未配線（DESIGN-shell-v2 §11 の残件）で、見た目が「デバッグ用リスト」に固定されている。**デスクトップらしくない最大の原因はこれ。**
- **X2. 面の階層がない。** 背景・面・浮動面の区別がなく、全要素が「白い矩形＋1px の薄い枠」で同格に並ぶ。Fluent は elevation（影＋輪郭）で階層を作り（S5 の系統）、GNOME は boxed list（面の上にグループ化した行）で作る。現行の border 色 #C6C6CC は白背景に対して約 **1.7:1** しかなく、WCAG 1.4.11 がコントロールの識別に求める 3:1（S12）を満たさない。つまり「どこが押せるのか」が色覚・輝度の面でも弱い。
- **X3. タッチターゲットが基準未満。** 現行トークンは control_h=36、row_h=32。Apple 44pt（S9）、Material 48dp（S11）、当プロジェクト自身のアシスト/OSK の 56px と比べても小さい。抵抗膜＋1本指では誤タップのコストが高い（押し直しは全て単一指の往復になる）。WCAG 2.5.8 の 24px（S12）は「Web の最低線」であって、指で使う専用端末の設計値ではない。
- **X4. 状態表現が弱い。** 選択は薄い青 (#B2D7FF、白との比 約1.5:1) の面だけ、押下・無効・フォーカスの表現は画面ごとにあったりなかったりする。色だけに頼る選択表現は、面の境界が弱く（X2 と同根）、「今どれが選ばれているか」が一瞥で読めない箇所がある（11_settings のサイドバーに至っては選択ハイライト自体がない）。
- **X5. レイアウトの溢れが複数アプリで再現する。** ツールバー右端のはみ出し（09/10）、画面下端の切れ（05/08/13）、一覧が伸びず空白が残る（09/10/12）。flex の縮小・折り返し・「入り切らない分はメニューへ落とす」逃がしが無く、**設計した寸法と実際の描画が一致していない**。本物のデスクトップでは「切れる」こと自体がバグとして扱われる水準の問題。
- **X6. 余白のリズムが画面に出ていない。** トークン上は unit=8 があるが、実際の画面では要素が画面端に張り付く（05 の左右マージンは約8px、09 のツールバーは端から端まで切れ目なし）。GNOME の 6/12（S2 系）、KDE の 4/8（S7）、Material の 8dp（S11）はいずれも「スケールを画面に見せる」ことが目的で、現行はその段階に届いていない。
- **X7. フォントの欠けと誤グリフ。** U+2212（−）がサブセットに無く、電卓の「−」キーとアシストの「音量−/輝度−」が空白になる（12/04）。OSK の候補バーには候補間に矢印様のグリフが並ぶ（06）。どちらも「製品でない」印象を直接作る。
- **X8. 世界観の不整合。** デスクトップだけが濃紺のダークな世界で、アプリとパネルはライトテーマ。デスクトップ背景とパネルの境界も唐突。主要 DE はシェル全体が1つの素材・色系で統一されている（S3/S5/S10）。現行は「ダークな壁紙＋ライトなパネル＋白い巨大カード」の3者が無関係に置かれている。
- **X9. 開発用表示の漏れ。** 「バックエンド: mock」（11）、「[Folder]」（09）、「タスクなし」（01）など、内部状態や英語の型名がそのままユーザー画面に出ている。本物の製品画面には出ない種類の文字列。

## 1.1 01_desktop — デスクトップ

現状: 濃紺一色の背景に、画面の左半分を占める**巨大な白い長方形が2つ**（「ライター」「メモ」のラベルが中央に小さく出る）。四隅には小さなティック（切り取り線のような印）がある。下部パネルは「アプリ」「切替」のテキストボタン、「タスクなし」の文字列、右に「電池 72% 音量 40 09:41」のテキスト詰め込みと「設定」ボタン。右下に「補助」の白枠ボタン。

診断:
- **デスクトップの基本形が成立していない。** 本物のデスクトップは「壁紙＋小さなアイコン（48px 級）＋ラベルのグリッド」が基本形（Windows/macOS/GNOME/Plasma Mobile 共通、S6/S10/S13/S14）。現行の2枚はアイコンではなく「窓でもカードでもない白い板」で、大きさ（約245×330px）に意味がない。四隅のティックはリサイズハンドルかウィジェット境界の名残りに見え、製品画面の要素として読めない。
- アイコン画像が解決できない場合のプレースホルダが全面に出ている（X1 の最たる例）。アイコンがないので、2つの「何か」がアプリなのか文書なのかすら判別できない。
- **タスク表現がない。** 実行中アプリはパネルにアイコンで並び、アクティブが分かるのが標準（Win タスクバー、KDE タスクマネージャ、macOS Dock の実行ドット、S6/S8/S10）。現行は「タスクなし」という状態説明の文字列があるだけで、タスクがある場合の見え方が設計として読み取れない。「切替」ボタンで循環させる方式は、窓が3つ以上あると「今どれにいるか」が分からなくなる。
- トレイが「電池 72% 音量 40」という**テキストの羅列**で、アイコン＋数値の形式でない。音量 40 が % なのか段階なのかも不明。時計だけが右端に埋もれている（GNOME は時計を中央に置いて視認性を確保する、S3）。
- 「補助」ボタンは素の白枠矩形で、フローティング要素としての浮き上がり（影・角丸）がないため、デスクトップ上の他の白い板と同格に見える。

## 1.2 02_launcher — ランチャー

現状: 画面全体を白い2ペインのリストが占める。上に検索欄、左にカテゴリ（All/Accessories/Development/Education/Game/Graphics/Network の英語名）、右にアプリ名のテキスト行（アイコンなし）。中段に「ピン留め 切替」という行、下段にピン留め2件のテキストリスト。パネルが下に残ったまま重なっている。

診断:
- **スタートメニュー/ランチャーの体をなしていない。** Win11 の Start は「検索（上）→ピン留めのグリッド→おすすめ→フッター（ユーザーと電源）」の浮動パネル（S6）。Kickoff は「検索＋Favorites（グリッド）＋カテゴリ＋下部にセッション操作」（S8）。GNOME のアプリグリッドはカテゴリ分類自体を避け、検索とグリッドで構成する（S3）。現行はそのどれでもなく、「設定ダイアログのような分類リスト」で、開いた瞬間に「アプリを選ぶ場所」という役割が伝わらない。
- アプリが**名前だけ**で、アイコンがない（X1）。17件あるのに7行しか見えず、スクロールバーも端の手がかりもないため、**残り10件の存在自体に気づけない**。発見可能性の欠陥であり、スクロール可能であることの視覚的手がかりは必須（後述の仕様でスクロールバーの常時表示を定める）。
- カテゴリ名が freedesktop の英語名そのまま。日本語 UI の中でここだけ英語なのは一貫性を欠く。また Office/System/Utility が無く、該当アプリは All でしか辿れない（カテゴリの写像漏れ）。
- 「ピン留め 切替」という行は、セクション見出しとボタンが同居して意味が取れない。本来ピン留めは「グリッドの見出し＋アイコン群」として見せるもの。
- 全画面化しているため、デスクトップ（作業文脈）との接続が切れる。浮動パネル型なら「開いた場所（パネル左端）の近くに出る」空間的な対応も保てる。

## 1.3 03_quicksettings — クイック設定

現状: パネルの上に白い帯が開き、Wi-Fi 行（トグルスイッチが砂時計形に描画される）＋「未接続」、音量スライダー（つまみが砂時計形）、全幅ボタン「リピート: 標準」。

診断:
- **クイック設定の標準形は「トグルのタイル/ピルのグリッド＋スライダー群」**である。Win11 のクイック設定はトグルのグリッド、GNOME のクイック設定はピル型トグル、Phosh は上パネル展開でトグルとスライダーを出す（S6/S3/S13）。現行は「Wi-Fi 1行＋スライダー1本」で、輝度がない（バックエンドは実装済みなのに画面にない）ため、クイック設定としての用をなしていない。
- 「リピート: 標準」はキーボード設定であり、クイック設定に置く項目ではない。置き場所の分類ミスは「使いづらさ」に直結する（探す場所を間違える）。
- スイッチとスライダーつまみの**砂時計形描画は描画バグ**（tk_widgets.c の Switch/Slider）。楕円/円の描画が潰れており、コントロールの種類自体が読めない。
- Wi-Fi の状態が「未接続」の文字だけで、トグルの ON/OFF と接続状態の関係が1つの行に混在している。標準形では「タイル=ON/OFF、タイル内の副テキスト=接続先/状態」と役割が分かれる。

## 1.4 04_assist — 単一指アシスト

現状: 右下の「補助」ボタンから、画面右半分に 2列×4行の大きな白ボタン（音量＋/音量、輝度＋/輝度、前ページ/次ページ、ランチャー/ロック）が開く。

診断:
- ボタン寸法（56px）は本書の基準でも正しい（残すべき部分）。問題は中身の表現。
- **「音量」「輝度」としか見えないボタンがある**（− が U+2212 欠けで消える、X7）。＋側と見分けがつかないペアは誤操作に直結し、アシスト（操作補助）の目的と真逆。
- パネルに影も角丸もなく、背面のデスクトップの巨大カードと白同士で重なって境界が読めない。浮動シートとしての体裁（面＋影＋角丸）が必要。
- 現在値（音量 40、輝度 60%）が表示されず、押した結果がその場で確認できない。アシストは「押す→変わる→見える」の即時フィードバックが本体機能。
- アイコンがなく全て文字。音量/輝度/ロックはアイコンの方が速く読める種類の操作。

## 1.5 05_greeter — グリーター

現状: 「Brainux」の小ラベル、ユーザーリスト（ぶれいん太郎/ゲスト）、パスワード欄（●マスク）、全幅の「ログイン」ボタン、その下に OSK。OSK の最下段は画面下端からはみ出して切れている。

診断:
- **実在のサインイン画面の基本形は「大きな時刻/日付＋ユーザー（アバター）＋認証カード」**である。Win11 のサインイン、GDM、Phosh のロック画面（時刻/日付＋状態アイコン、S13）は全てこの形。現行は時刻表示すらなく、「事務フォームの縦積み」で、電源を入れた直後の顔になっていない。
- **OSK の最下段が切れているのは致命的**。ログインに必要な文字（記号/英数/確定）が押せない可能性がある。レイアウトが 800×480 に収まっていない（X5）ということで、見た目の問題ではなく機能の問題。
- ユーザー選択が素のリスト行で、アバターも「選択中」の強い表現もない。複数ユーザー時の切り替え方法も読み取れない。
- パスワード欄とログインボタンの間の大きな空行など、グループ化（近いものは近く、関係ないものは離す）が崩れている。認証に必要な要素は1つのカードにまとめるのが標準形。
- 良い点: パスワードのマスク表示とフォーカス枠は機能している。土台はある。

## 1.6 06_osk_qwerty_ime — OSK（QWERTY＋IME 変換中）

現状: 変換中文字列（下線付き）、候補バー（候補27件、「今日」が選択色、候補間に上下矢印様のグリフ）、QWERTY 4段。

診断:

# 第2部: 再設計仕様

## 2.1 採用する原則と、採用しないもの

採用（根拠つき）:
1. **見えるボタンで操作する（ジェスチャ前提にしない）。** Lomiri は全操作を端スワイプに寄せたが、実利用では発見可能性と手数の問題が指摘されている（S15）。本機は抵抗膜・単一指で、スワイプの誤判定コストも高い。全ての主要操作は常時見えるボタン/アイコンを持ち、ジェスチャは「あってもよい近道」に留める。
2. **シェルの文法は3者の共通項に寄せる。** パネル（下）＋ランチャー＋トレイ＋時計という構成は Win（S6）/KDE（S8）の共通形で、GNOME も「左=入口、中央=時計、右=ステータス」の役割分担は同じ（S3）。独自デザインとは「構成要素の発明」ではなく、この共通文法の上での素材・色・寸法の統一を指す（ユーザーの既定方針どおり）。
3. **アイコン＋ラベルを識別の基本単位にする。** アイコンは Papirus の単一セットを全画面で使う（既定方針）。アイコンが引けない場合のフォールバックは「汎用アイコン1種」に限定し、白い板のような全面プレースホルダは使わない。
4. **面の階層は最大3層。** 背景（bg）→面（surface / surface_alt）→浮動面（ランチャー、メニュー、ダイアログ、シート）。浮動面だけが影を持つ（§2.5）。

採用しないもの:
- 画面上部のグローバルメニューバー（macOS 式、S10）。本機はパネルが下部で、アプリは全画面に近い使い方になるため、二重のバーは縦 480px を圧迫する。アプリのコマンドはアプリ内ヘッダーに置く（GNOME ヘッダーバー式、S1）。
- ブラー/半透明マテリアル（Fluent の Mica/Acrylic、macOS のすりガラス）。GPU がなく転送もダメージ駆動のため、**代替として不透明な浮動面＋1px 境界＋オフセット影**で階層を表現する（§2.5）。
- ホバー前提の発見（ツールチップ頼みの機能配置）。抵抗膜ではホバーが存在しない。ツールチップは補助に留め、機能はラベルで読めるようにする。

### 影（GPU なし前提の代替表現）

- 影は**浮動面のみ**。表現は「1px の border（#8A8A92 系）＋右下 4px オフセットの単色シルエット（黒 25% 相当の固定色を、面を描く前に1回だけ描く）」。ぼかしは使わない。ダメージ矩形は影の分だけ広げる（転送量の増加は浮動面の出現時のみで、常時コストにはならない）。
- アプリ内の面（カード、グループ）には影を付けない。階層は surface_alt と区切り線で作る。

## 2.3 DE の画面構成（再定義）

以下、要素ごとに「本物のデスクトップのどの構成要素に対応するか」を明記する。

### デスクトップ
- 全面が壁紙（画像、または desktop_bg 色）。その上に**アイコングリッド**（セル 76×76、左上から縦に流す、間隔 8）。
- 置くのは**ピン留めだけ**（全アプリはランチャーの役目。Win11/macOS の初期状態と同じ整理、S6/S10）。
- アイコン下のラベルは壁紙上でも読めるよう、白文字＋1px の暗色シャドウ（ぼかしなし、オフセット描画）とする。
- ウィジェット類（時計等）は置かない。デスクトップは「静かな場所」に徹する（GNOME の素のデスクトップ、S3 と同じ判断）。

### パネル（下部、56px）
左から右へ:
1. **ランチャーボタン**（3×3 グリッドのアイコン、48×48 ヒット）— Win の Start / KDE の Kickoff ボタンに対応。
2. **タスク領域**: ピン留めと実行中を同じ並びに置く（アイコン 40）。実行中は下に 3px のインジケータ、アクティブは surface_alt の面＋インジケータを accent に。タスクがない場合に文字列は置かない — KDE のアイコンタスク、macOS Dock の「ピン＋実行中＋ドット」（S8/S10）と同型。「切替」ボタンは廃止（タスクを直接タップするのが標準で、循環ボタンは窓3つ以上で破綻する）。
3. （中央は空ける。時計の中央配置は GNOME 式（S3）だが、800px 幅ではタスク領域と競合するため本機では右グループに置く。判断として明記する。）
4. **トレイ**: Wi-Fi、音量、電池の**アイコン**（電池は残量 % の caption を併記）。トレイ全体がクイック設定を開くボタン（ヒット領域として一体）。Win のトレイ、GNOME のシステムステータス領域（S6/S3）に対応。
5. **時計**: HH:MM（body、太字）。タップで通知＋カレンダーのシートを開く。
6. **設定**（歯車アイコン）。テキストボタン「設定」は廃止。
7. 右端に **アシストボタン**は置かない（アシストは従来どおり右下フローティング、§2.3 アシスト参照）。パネルとフローティングの二重配置はしない。

### ランチャー（スタート）
- パネル左端のボタンから開く**浮動パネル**（角丸 8、影つき）。寸法: 800×480 では **幅 600 × 高さ 408**（パネルの上に 8 の間隔）。480×272 では**全画面シート**に切り替える（Phosh の Overview 方式、S13）。
- 内部構成（上から）:
  1. **検索欄**（高さ 48、開いた時点でフォーカス。物理キーボードでそのまま打てる。OSK はテキスト欄タップ時のみ）
  2. **ピン留め**（見出し title＋グリッド、セル 76、4列×2行=8件を初期表示、残りはグリッド内スクロール）
  3. **最近使った**（行 48、アイコン 24＋名前。件数ベースで上限管理＝既存の reg 実装どおり）
  4. **カテゴリチップ列**（すべて/アクセサリ/システム/…、**日本語名**。freedesktop カテゴリの日本語写像表をシェル側に持つ）＋チップで絞った場合はグリッドが全アプリ表示に切り替わる
  5. **フッター**: 左にユーザー名、右に電源ボタン群（ロック/再起動/電源オフ、各 48 ヒット）— Win11 Start のフッター、Kickoff の Leave（S6/S8）に対応
- 全アプリのグリッドには**スクロールバーを常時表示**する（thumb の大きさで全体量が分かる）。「7行しか見えず残りに気づけない」（1.2）の恒久対策。
- カテゴリの2ペインリスト形式は廃止する。

### ウィンドウ枠
- タイトルバー 40px: 左にアプリアイコン 20＋タイトル（heading）、右に最小化/最大化/閉じる（各 40×40 ヒット、グリフは中央に小さく）。閉じるは押下時のみ danger 面。
- フォーカスのない窓はタイトル文字を text_dim にする（フォーカス窓との区別）。
- 最大化時は角丸 0、タイトルバーはパネルに接するまで使う（S5）。
- ドラッグ移動はタイトルバー全域（GNOME HIG の「ドラッグできる空白を残す」、S1）。リサイズは隅 32 のハンドル（単一指で掴める大きさ）。

### クイック設定
- トレイのタップで開く浮動パネル（幅 360、角丸 8、影）。パネルの右端に寄せて出す。
- 構成: **トグルタイル 2列グリッド**（各タイル 高さ 72: アイコン＋ラベル＋状態値の caption。Wi-Fi 等）＋**スライダー行**（輝度、音量: アイコン＋スライダー＋値）＋フッター行（「設定を開く」「電源」）。
- キーボードリピートのような詳細設定は置かない（設定アプリの領分）。置くのは「今すぐ切り替えたいもの」だけ（Win11/GNOME/Phosh のクイック設定の共通項、S6/S3/S13）。

### 通知
- トースト: 画面上部中央の浮動カード（角丸 8、影、幅最大 480）。タップで消去、自動消滅は既存モデルどおり。
- 通知一覧: 時計タップで開くシートに、カレンダーと並べて表示（GNOME の時計→通知＋カレンダー、S3）。既存の通知キュー（上限4件）の受け皿として定義する。

### グリーター
- 全画面レイアウト: 上部 1/3 に**時刻（display 28 ではなく時計として 48 級に拡大してよい唯一の場所）＋日付**、中央に**認証カード**（surface、角丸 8、幅 400 を中央寄せ）:
  - アバター（円 64、頭文字 or 汎用アイコン）＋ユーザー名（title）
  - パスワード欄（高さ 48、マスク表示は現行の実装を維持）
  - ログインボタン（高さ 48、accent 面＋白文字）
  - ユーザーが複数いる場合はカードの下に切替リスト（行 56: アバター 32＋名前）
- OSK は「キーボードを開く」ボタンで**下部シートとして出す**。出す場合は画面下 45% を占有し、認証カードはその分だけ上にずれる（重ねて切らない。1.5 の致命点の対策）。出していない時はカードは中央。
- 480×272 では時刻を title サイズに落とし、カードを優先する。
- 右下に電源メニュー（再起動/電源オフ、48 ヒット）を置く（サインイン画面の標準装備）。

### 単一指アシスト
- 寸法設計（56px ボタン、全行 56px）は正しいので**維持**し、視覚と情報だけを再設計する:
  - フローティングボタン: 円形 56、アイコン（手/指系ではなく、既存の Papirus から「補助」相当のグリフ）、影つき。ラベル「補助」の文字は持たない（アイコン＋開いた先の見出しで説明する）。
  - パネル: 右下から開くシート（角丸 8、影、幅 320）。各行は「アイコン＋ラベル＋現在値」（音量 40 のように）を持ち、＋/− は行の左右端のボタンではなく**行全体を1項目として「下げる/上げる」の2ボタンに分ける現行構造を維持**するが、ラベルはアイコンのグリフ（− はフォント修正後に正しく出る前提、§3 P0）で表現する。
  - 開いている間も背面の文脈（どのアプリの上か）が分かるよう、シートは画面の右下 40% 以内に収める。

## 2.4 各アプリのレイアウト再設計方針

共通原則（全アプリ）:
- アプリ内最上部は**ヘッダー行 48px**（GNOME ヘッダーバー式、S1）: 左=戻る/画面タイトル、中央は空ける（ドラッグ領域）、右=主要アクション（アイコン＋ラベル、最大3つまで。それ以上はメニューへ）。
- **ツールバーの溢れ対策を原則化する**: 入り切らない項目は「»」メニューへ自動で落とす。はみ出して切れる状態を作らない（1.9/1.10 の恒久対策。これはツールキット側の部品要件として §3 に挙げる）。
- リストは行 48/64、選択は面＋左バー（§2.2）。スクロールバーは常時表示。
- 開発用文字列（mock、型名、内部パス）をユーザー画面に出さない。必要な場合は env 明示時のみ。

### bd-files
- ヘッダー: [戻る][進む][上へ] のアイコンボタン（各 48 ヒット）＋**パンくず**（階層ボタン列、現在地は heading＋面）＋[検索トグル][表示切替（グリッド/リスト）][メニュー]。パスのテキスト入力はパンくずのタップ切替（または物理キーの Ctrl+L）で出す補助手段にする（S4 の Nautilus/Dolphin 方式）。パスの二重表示は廃止。
- サイドバー（幅 176）: ホーム / ダウンロード / ドキュメント / 画像 / 音楽 / **SD カード** / ゴミ箱。下部に空き容量の caption＋細いバー。
- 一覧: 行にアイコン 24＋名前（フォルダはフォルダアイコン）。グリッド表示はセル 76。型名のテキスト（[Folder]）は出さない。**一覧は残り全高を使う**（伸びない問題の修正が前提）。
- 操作（開く/新規/名前変更/コピー/切取/貼付/削除/復元）は常時表示の2段ツールバーをやめ、**選択時に下部へ出るアクションバー**（高さ 56、主要操作のみ＋残りはメニュー）に移す。未選択時は「新規」だけをヘッダー右に置く。
- ステータスバー: 「9 項目」＋選択時は「1 件選択中 — 名前」。

### bd-notes
- 3ペイン維持（フォルダ 160 / ノート一覧 224 / 編集は残り）。ペイン間の区切りは border_line。
- 検索はヘッダーのトグルで開く**検索バー**（編集ペインの上部に差し込む。入力＋件数＋前/次。置換は展開時のみ2行目）。常時2段占有をやめる。
- 書式ツールバーは編集ペイン上部に**1段だけ**（見出し/太字/斜体/下線/箇条書き/番号）。入り切らない分は » へ。
- フォルダ一覧・ノート一覧は全高＋スクロールバー常時表示。
- エディタは残り全域を使う。行間はフォント実値どおり。

### bd-settings
- サイドバー: 行 48、**選択中は面＋左バー＋太字**（現在地を必ず示す）。検索欄はサイドバー上部（48）。
- ページ: **グループ見出し（heading）＋行リスト**。行は高さ 56 で「ラベル（左）＋値/コントロール（右）」の1行完結（輝度なら [輝度] [スライダー] [60%]）。トグル行はラベル＋スイッチ（右端）。遷移行はラベル＋現在値（caption）＋ › 。

### bd-calc
- 表示部: 式（caption、右寄せ）＋結果（display 28、右寄せ）の2段を上部に固定。
- キーパッド: 残り全域に伸びるグリッド。列は等幅、行は等高。数字キーは surface、演算子列は surface_alt、= は accent 面＋白文字、C/AC は danger の文字色。**( と ) は同じ行に並べ、孤立キーを作らない**（グリッド定義の見直し）。

### bd-player
- **下部に Now Playing バーを固定**（高さ 72）: 左に曲アイコン 48（アルバムアートがあれば画像）、曲名（body）＋アーティスト（caption）、その下/右に進行バー（つまみ正円 28、経過/総時間の caption）、[前へ][再生/一時停止（56 の円形、accent）][次へ]。音量はアイコン＋タップで展開するスライダー（常時表示でラベルと重ねない）。
- 本体はライブラリ: タブ（曲/アルバム/アーティスト/ジャンル/プレイリスト）を上部に分離し、検索・再スキャンはヘッダー右のアクションに分ける（ナビゲーションとコマンドを混ぜない）。

### OSK
- キー描画: 角丸 6、キー間ギャップ **4（800幅）/ 2（480幅）**、キーの面は surface、押下時は accent の薄い面。文字はキー中央、body サイズ。シフト時はキーの文字表示を大文字に切り替える（状態を見た目に反映）。
- 候補バー: 高さ 48。候補はチップ（角丸=全丸、内側パディング 12）で、**区切りは 8 の空白のみ**（グリフ区切りは廃止）。選択中は accent 面＋白文字。候補バーの右端に候補一覧の展開ボタンを置く。

- 記号ページ: グリフは body より大きく（20 級）中央に。カテゴリ切替は上部のチップ列（高さ 40）にする。状態トグル（半角等）は面の反転で ON/OFF を示す。

### その他のアプリ（bd-clock / bd-tasks / bd-recorder / bd-pkg / bd-admin / ブラウザ）
- 個別の作り込みは各アプリのフェーズで行うが、共通原則（ヘッダー48、行48/56、面のグループ化、溢れたらメニュー、開発文字列を出さない、スクロールバー常時）をそのまま適用する。特に bd-recorder の録音ボタン、bd-clock のアラーム行は「行」の形に揃える。

## 2.5 制約への適合（RAM 128MB / fbdev / GPU なし）

- **ブラーの代替**: 浮動面は不透明（surface）＋境界＋オフセット影（§2.2）。壁紙の上に直接文字を置く場所（デスクトップのアイコンラベル）だけ、1px の暗色シャドウで可読性を確保する。
- **影のコスト**: 影は浮動面の出現時に1回描くだけで、常時コストはゼロ。ダメージ矩形は影の分（+4px）だけ広がる。
- **アニメーション**: 既定トークンの 150–200ms を維持するが、動かすのは浮動面の出現（スライド/フェードなしの位置移動のみ、対象は小さい矩形）までに限定し、全画面遷移のアニメーションはしない。ダメージ駆動転送と矛盾しない範囲に限る。設定で無効化できること。
- **アイコンのメモリ**: アイコンのデコード/スケールはシェルの単一キャッシュ（予算 2MiB、DESIGN-shell-v2 §2.1）が担い、再設計で増える使用箇所（パネル、ランチャー、デスクトップ、files）は全てこのキャッシュを共有する。新規の常駐メモリは増やさない。
- **フォント**: サイズ階層を5段に増やしても、グリフキャッシュはフォント毎 1024 グリフの既存予算内（サイズ違いは別エントリになるため、実測で RSS を確認すること。§3 の検証項目）。

## 検証（全フェーズ共通）

- 各 P の完了ごとに `screenshots/` のハーネスで該当画面を再撮影し、本書第1部の診断項目が消えているかを目視で突き合わせる。再撮影した画像は本書の各診断への「修正後」として残す。
- 数値の検証: ターゲット寸法と行高は撮影画像から実測する。コントラストは §2.2 の計算値と実装値（tk_theme の実値）が一致することを確認する。
- 合格判定は従来の総則どおり、SD イメージ＋QEMU ゲスト/実機での実操作で行う。ホスト撮影は中間証拠に留まる。
- 恒常原則の確認: アイコンキャッシュの予算（2MiB）超過なし、シェル PSS が予算（約10MiB）内に収まること、ダメージ転送量が再設計で悪化していないこと（浮動面の影は出現時のみ）。
