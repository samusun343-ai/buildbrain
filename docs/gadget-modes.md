# ガジェットモード設計 — 1機種専用だからできる特化

PW-SH6 は汎用 PC ではない。機種が1つに決まっているからこそ、
「挿せばその物になる」特化機能を OS 側に最初から組み込める。

ただし「何に使うか」は使う人が決めることなので、モードは固定の
プリセットではなく、ユーザが自分で定義できるプロファイルとして
実装する (brain-mode)。下記のモードは初期プロファイル兼サンプルで、
/etc/brain-modes/<id>.conf に key=value を置けば誰でも追加・変更できる。
ここでは実測で確認済みのハードウェア能力だけを前提にする。

## 前提 (検証済みの能力)

- USB OTG: ホスト (EHCI 起動確認済み) とデバイスの両対応
- カーネルに USB configfs gadget 入り (NCM / RNDIS 有効)。HID は defconfig 追加のみで可
- USB シリアル変換 (CP210X / FTDI / PL2303) はカーネル組み込み済み
- ストック構成に ethernet_gadget.service が既にある (USB ネットワーク)
- 音声出力 (BU26154、実証済み)、物理キーボード + 抵抗膜タッチ、輝度制御、バッテリー、RTC
- 128MB RAM / ARM926EJ-S。重い処理は相手側 (接続先) に寄せる設計が基本

## モード一覧

### 1. コントロールデッキ (USB HID gadget)
PC に挿すと USB キーボードとして認識され、物理キーと画面ボタンが
マクロ/ショートカットになる。画面には接続先の状態 (音量、再生中、
CPU など) を表示。Stream Deck 的だが物理キーがある分だけ強い。
- 必要: CONFIG_USB_CONFIGFS_HID 追加、bd-deck アプリ、相手側コンパニオン (任意)
- 実装難度: 低 (gadget 側は configfs の定型作業)

### 2. USB ネットワークガジェット (整備)
挿すだけで NCM/RNDIS リンクが張られ、SSH とファイル共有が開く。
ドライバ探し不要の「挿せば入れる」ラズパイ代替の入口。
- 既存 ethernet_gadget を braindesk の設定と連動させる (ON/OFF、IP 表示)

### 3. bot サーバ
常時起動・低消費電力・バッテリー付き (停電で落ちない) を活かした
軽量 bot 基盤。Webhook/ポーリング型チャット bot、通知 bot、定時実行。
- systemd テンプレート + サンプル bot 同梱、設定アプリから起動状態を管理
- RTC があるので時刻基準のタスクが正確

### 4. ラズパイ簡易代替キット (サーバモード)
設定アプリで束ごと ON/OFF できる小さなサーバ群:
DNS/DHCP (dnsmasq)、MQTT (mosquitto)、WireGuard、軽量 Web、ファイル共有。
USB-シリアル/I2C ドングル経由でセンサー類も相手にできる。
- 個別に入れるのではなく「サーバモード」として設計し、メモリ予算を束で管理する

### 5. シリアルコンソール端末 (クラッシュカート)
USB-シリアル対応がカーネルに入っているので、他機器のコンソールを開く
レスキュー端末としてそのまま使える。画面+物理キーボードが効く用途。
- bd-term のプロファイル機能として実装

### 6. ステータスモニタ / 常設ダッシュボード
接続先 PC やサーバの状態 (CPU、温度、通知、ビルド結果) を
ネットワーク経由で受けて表示する第2画面。時計+カレンダーの常設表示もここ。
- braindesk の「ダッシュボード」シーンとして実装、受け口は小さな HTTP/MQTT

### 7. 学習デッキ
本来の辞書機の延長。Anki 形式のデッキを取り込んで間隔反復で再生する。
- bd-learn アプリ。デッキは SD/ネットワークから取り込み

### 8. 録音・再生ステーション
再生は実証済み。録音は実機での切り分け待ちだが、通れば
ボイスレコーダ+簡易文字起こし (起こしは接続先/クラウド側) の拠点になる。

## 土台の仕組み

モードは「アプリの寄せ集め」にしない。次で統一する:
- systemd target でモード単位にサービスを束ねる (通常 / デッキ / サーバ / 端末)
- 設定アプリに「モード」画面を置き、切替と各モードの設定を GUI で完結させる
- モードごとにメモリ予算を持ち、brain-measure で実測して予算超過を直す

## 実装順序

1. モード基盤 (target + 設定のモード画面)
2. コントロールデッキ (カーネル1行 + bd-deck)
3. USB ネットワーク整備 (既存 gadget の設定連動)
4. サーバモード (dnsmasq / mosquitto / WireGuard の束)
5. bot 基盤 (テンプレート + サンプル)
6. ダッシュボード、学習デッキ、シリアルプロファイル

深層最適化 (NetworkManager 代替、統廃合、カーネル棚卸し) と並行し、
軽くなった分をモード側の予算に回す。
